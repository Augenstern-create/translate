# P5 阶段总结与验收报告

- 日期：2026-11-07
- 阶段：**P5.6（汇总验收）**，收口整个 P5（P5.0 → P5.5）
- 关联：`docs/29`（P5 前置勘察）、`docs/30`（P5-01 Android 工具链）、`docs/31`（部署清单）、
  `docs/32`（权限边界，外部审查稿）、`docs/33`（P5.1）、`docs/34`（P5.2–P5.3）、`docs/35`（P5.4）、
  `docs/36`（P5.5）、`docs/01` ADR-054～060
- 一句话结论：**P5 的功能面在 Windows 实体机与 Android 模拟器上都拿到了可复现证据；但"跨平台 = 全部能力可用"
  不成立**——Windows 上进程隔离 worker（Bergamot）按平台门禁**不可用**，Android 上 ARM64 运行与物理设备性能
  **未验证**，5 条发行阻断项**仍然 open**。所以 P5 的裁定是 **Conditional（条件性通过）**，不是"全平台已支持"。

---

## 1. 按 ADR-051 的三分口径

| 维度 | 结论 | 依据 |
|---|---|---|
| **工作包交付** | **完成**：P5.0～P5.5 六个工作包全部交付，各有 `docs/*` 报告与 tag（`p5.0`…`p5.7`） | 本报告 §3 的索引表 |
| **门禁闭合** | **未闭合**：5 条发行阻断项（G12/G11/G06/G08/D-46）**全部仍 open**，`check-release.py --release-mode` 必须继续 FAIL | `fixtures/release-blockers.json`；`docs/34`/`docs/35` 的复跑记录 |
| **候选可用性** | **条件性可用**：Linux 全能力（P3 结论不变）；Windows 核心/词典/规则/资源/CLI/ORT 可用、worker 不可用；Android 模拟器功能可用、ARM64 运行与物理性能未验证 | 本报告 §2 的平台证据表 |

**P5 完成定义（`docs/32` §8）核对**："真实 Windows 项目工作区内，SDK 核心、词典/规则/资源管理和
至少一个所选 NMT 运行时达到有证据支持的功能性目标" → **达成**（`docs/34`：W1–W10 全绿 + ORT 24 条真实模型用例；
`docs/35`：Windows 存活探测 + 跨进程资源 6 条不变量）。Android 按用户决定**单列**，不作为 Windows 验证的失败项。

## 2. 平台证据表（P5 收口版）

图例：✅ 有真机/真运行时证据　🟡 有证据但口径受限（模拟器/静态链接变体）　⛔ 平台门禁明确拒绝　❔ 未验证

| 能力 | Linux x86_64 | Windows x86_64（实体机 NAN-WINDOWS） | Android x86_64（AVD gms2, API 34） | Android ARM64 |
|---|---|---|---|---|
| 核心 pipeline / 插件路由 | ✅ | ✅ | ✅（CLI 实测） | ❔（仅编译） |
| 词典（FST + SQLite，`bundled`） | ✅ | ✅（W5） | ✅（真词典包 lookup） | ❔ |
| 规则 / 保护跨度 | ✅ | ✅ | 🟡（管线可运行；mock 回显无法断言改写） | ❔ |
| 资源仓库（安装/激活/回滚/卸载/audit/租约） | ✅ | ✅（含跨进程 6 条不变量） | ✅（install/list/inspect/audit + 拒绝卸载激活版本） | ❔ |
| CLI（含 mock 引擎） | ✅ | ✅（W8） | ✅ | ❔ |
| ORT 本地 NMT | ✅（`none` 静态 CPU 变体） | 🟡（`directml` 静态包；能真翻译，但**与 Linux 非同一变体，性能不可比**） | ❔（未尝试；模型 110 MB 未上设备） | ❔ |
| 进程隔离 worker（Bergamot） | ✅ | ⛔ `CapabilityUnavailable`（按设计） | ⛔（同门禁） | ⛔ |
| 进程存活判定 | ✅ `/proc` | ✅ `kernel32`（P5.4 新增） | ✅（同一实现） | ❔ |
| 移动端性能（速度/耗电/温度/峰值内存） | n/a | n/a | 🟡 模拟器口径，**不可外推** | ❔ |

**这张表就是 P5 的全部结论**；凡不在表里的组合，一律视为"未验证"，不因为"能编译"而算通过。

## 5. P5 新增/更新的 ADR

| ADR | 内容 |
|---|---|
| ADR-054 | 平台证据按"实体机 > 模拟器/虚拟机 > CI runner"分层，只认最高可得一层 |
| ADR-055 | Android 交付分"编得出/装得上/调得通"三段链；x86_64 产物不得充当 ARM64 证据 |
| ADR-056 | 环境证据只由只读、版本化 schema 的脚本采集 |
| ADR-057 | **唯一可写工作区 + 逐项审批**（工作区外只读；管理员权限不构成预授权） |
| ADR-058 | 跨平台验证用 `cfg` gate 表达不可达；两平台用例数必须同时给出并解释差值 |
| ADR-059 | Windows 存活判定用 `kernel32` 裸 FFI，创建时间作启动标识，未知仍返回 `Unknown` |
| ADR-060 | Android 以模拟器功能验证 + 交叉编译合规为准；物理设备性能单列"未验证" |

## 7. P5 结论

> **P5 = Conditional（条件性通过）。**
> 证据面：Windows 实体机 W1–W10 全绿（333 passed / 0 failed / 60 ignored，含 ORT 24 条真实模型用例）、
> Android x86_64 模拟器上真 SDK 跑通（词典/资源/CLI/识别/翻译）、ARM64 仅编译合规。
> 不可用面：Windows 的进程隔离 worker 按平台门禁拒绝（不是缺陷，是 ADR-024/042 的既有决策）。
> 未验证面：ARM64 运行、移动端物理性能、Windows 性能口径。
> **不得**以本报告对外宣称"全平台已支持"，也不得据此关闭任何发行阻断项。
