## 5. 本阶段偏差

- **D-141：P6 的 J-12 在 Windows 上跑到的是"JNI crate 参与 workspace 编译"的结果，而不是"JNI 库在 Windows 上被加载"。**
  `translator-jni` 的 `cdylib` 在 Windows 上是 linker 无关的空壳（JNI 符号只为 Android 准备），
  Windows 侧真正验证的是"加了绑定层之后核心不回退"。这条口径必须保留，否则会被读成"Windows 也能用 JNI"。
- **D-142：`AlreadyClosed` 属绑定层自造码，未进 SDK 错误码表。**
  理由：它是句柄状态而非业务失败。影响：下游 Kotlin 侧需要**同时**处理 SDK 的 12 个码 + 这 1 个绑定级码。
- **D-143：`capabilities` 的 `runtimes` 字段是在实现中补的（`docs/39` 未列）。**
  已回写进 §3；后续若再加字段，按 minor 增量、`protocol_version` 不变（只在破坏性变更时 +1）。

## 6. 结论

> **P6 = Conditional（条件性通过）。**
> 达成：Android x86_64 模拟器上"完整 Rust SDK 经 JNI"可创建、可查词、可识别、可翻译（mock 路由，
> 能力表如实标注）、可查资源、错误可映射、并发关闭安全；Linux 379 / Windows 337 双侧回归无倒退。
> 未达成/未验证：坏资源与路径穿越（J-07）、模拟器 RSS/时延（J-14）、装卸生命周期（J-15）、
> APK 应用生命周期、真实 Android NMT、ARM64 运行。
> **不得**以本报告宣称"Android 端已可交付给最终用户"，也**不得**关闭任何发行阻断项。
