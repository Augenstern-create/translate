## 1. 执行摘要

P19-G 第一版把 P18-L 的词典/短语知识接入日常简单句组合：

- 新增 `CompositionEngine`（`crates/translator-core/src/composer.rs`）：
  数据化词表/量词/固定表达 + 通用 token、结构匹配和中文生成；
- 支持 11 类日常句型 + 固定表达优先；
- 规则结果进入 P17-A 的统一 Planner/Coordinator，`TranslationRoute::Rule`，
  走同一术语/质量/缓存/诊断链；
- 复杂结构、未知实词、部分匹配一律返回 `None`，继续 NMT；
- 独立组合集 **36 正例全部命中、5 反例全部回退**；
- 320 句对照 **chrF 0.5074 → 0.5172、BLEU 0.5060 → 0.5192，
  NMT 300 → 291、Rule 22 → 31，fatal 0、回归 0**；
- 默认回归 **526 passed / 0 failed / 60 ignored**；
  全特性 **539 passed / 0 failed / 67 ignored**。

这不是通用规则机器翻译。它只覆盖少量已验证日常简单句，未知结构仍交给模型。

## 2. G0 源码核验

核验并复用：

| 能力 | 位置 | 处理 |
|---|---|---|
| Planner/Route | `core/planner.rs`、`core/coordinator.rs` | 不新增 Planner；组合在 Coordinator 内尝试，失败继续原路径 |
| LanguageEvidence | `core/evidence.rs` | 组合结果写 `PatternKind::Rule` + 完整覆盖 |
| 词典/词性 | `resources/en-zh-ecdict@0.2.0` | 实词按词性查正式词典；查不到拒绝组合 |
| 词形 | `translator-analysis::EnglishLemmatizer` | booked→book、went→go、reading→read 等 |
| 模板 | `core/templates.rs` | 完整模板仍优先；组合在模板之后 |
| 上下文选义 | `core/context_sense.rs`、P17 证据 | book/light 由组合规则的词性/搭配数据选择 |
| 缓存 | `CacheKey` | route=Rule、rule/composition 版本进指纹 |
| 质量 | `quality::check` | 组合输出与 NMT 共用数字/占位/目标语言等检查 |
| 学习链 | `translator-learning` | 规则未覆盖仍产生 `RuleNotCovered` 等兜底原因 |

关键设计：**规则层只返回“匹配/候选译文/拒绝”**，不决定是否远程；
是否 NMT/Remote 仍由 `TranslationPlanner` 与显式授权决定。

### 3.2 数据化内容

`fixtures/rules/en-zh.composition.json`：

- 177 个词条：代词/助动词/情态词/常用动词/名词/形容词/副词；
- 27 条固定表达（问候、礼貌、where are you from、light blue 等）；
- 8 个短语动词（turn on/off、look after、get up、take off 等）；
- 高频名词量词；
- 过去式集合；
- 规则 id/version/source/target。

固定表达优先于结构规则；例如 `be afraid of` 不会被拆成 `am/afraid/of` 拼接。

### 3.3 尚未支持

- 定语从句/状语从句/多连接词（that/which/because/and 等）默认拒绝；
- 长距离指代、复杂时态、被动、比较、嵌套；
- 未收录实词（规则词表外）默认拒绝；
- 量词未知的 `a/an` 结构默认拒绝，不猜；
- 完整 SenseResolution 公开枚举未建立；book/light 等由规则数据+词性选择；
- 复杂句仍由本地 NMT/已授权 Remote 兜底。

## 4. 上下文选义（book/light）

CompositionEngine 的 `WordSpec` 支持多词性：

```json
"book": {"pos":"noun","zh":"书","classifier":"本","alternates":{"verb":"预订"}}
"light": {"pos":"noun","zh":"灯","classifier":"盏","alternates":{"adjective":"轻的"}}
```

规则按结构选择：

- `I read a book.` → 我读一本书（book=名词）；
- `She booked a room.` → 她预订了一个房间（booked=动词），
  过去式识别 + 词性验证；
- `Please turn on the light.` → 请打开灯（light=名词）；
- `The bag is light.` → 包很轻（light=形容词）；
- `The bag is light blue.` → 包是浅蓝色的（固定表达优先）。

每个实词都要在正式词典中找到对应词性（`parts_of_speech` + 非空义项），否则
组合拒绝。词表翻译是规则资源，不冒充词典自动选义；未验证词不会进入输出。

## 5. 中文组合与安全

### 5.1 语序/否定/疑问

- `Where is my phone?` → 我的手机在哪里？不是“哪里是我的手机”；
- `I don't like coffee.` → 我不喜欢咖啡；
- `Do you like tea?` → 你喜欢茶吗？；
- `She is reading a book.` → 她正在读一本书；
- `He went home.` → 他回家了（特殊处理 go home）；
- `She booked a room.` → 她预订了一个房间（过去+宾语，不重复加“了”）。

### 5.2 完整覆盖

每个 `try_*` 必须消耗全部 token；否则返回 `None`。因此：

- `Please open the door that was locked yesterday.` → NMT；
- `I like coffee because it is tasty.` → NMT；
- `Please open the door and close the window.` → NMT；
- `I want to buy a ticket to Paris.` → NMT。

独立测试集 5 条反例全部回退模型。

### 5.3 策略边界

组合只在：

- `TextKind::Sentence`；
- `AutoLocalFirst` 或 `DictionaryOnly`；
- source/target 匹配；
- 词典证据完整；

时执行。`LocalOnly`/`RemoteOnly` 不被规则旁路，仍按原策略走模型。
缓存键包含 `route=Rule`、composition id/version、资源指纹；规则版本变化会失效。

## 11. 明确区分

### 已实现

- CompositionEngine、数据词表/量词/固定表达、token span；
- 11 类句式 + 固定表达；
- book/light 规则级选义；
- 完整覆盖检查与 NMT 回退；
- Rule 缓存/诊断/统计；
- 独立正反例与 320/文档回归。

### 已验证

- 36 正例输出精确；
- 5 反例回退；
- 320 自动指标与 NMT 调用；
- 段落/文档结构；
- 默认/全特性回归。

### 尚不支持

- 定语/状语从句、复杂时态、被动、比较、指代、长难句；
- 规则词表外实词；
- 通用 WSD、完整 SenseResolution 公开模型；
- 复杂句质量提升。

### 必须进入 NMT

- 任何未完整覆盖/未知实词/复杂结构；
- 复杂从句、长句、段落深层语义；
- LocalOnly/RemoteOnly 策略请求。

## 12. 结论

P19-G 第一版已经让 P18-L 的词典/短语知识开始服务简单句翻译，而不是只做查询：
参数化组合、上下文词性选择、完整覆盖门禁与安全回退均已落地，320 句自动指标
有净提升且无回归。

但结论保持 **Conditional**：

- 只覆盖少量已验证日常句型；
- 177 词/27 固定表达的规则词表有限；
- 规则译文与 36 条正例仍需人工评审；
- 复杂语义继续 NMT；
- 不是通用规则 MT，也不是完整英语语法实现。

下一步应在 P20-K 学习链中收集规则未覆盖/消歧失败的真实样本，再按正反例扩充，
不应为了覆盖率盲目增加 Rust 分支。
