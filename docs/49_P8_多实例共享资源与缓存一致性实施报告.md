## 1. 实际实现内容

### 1.1 P8.1 JNI per-entry generation 多实例

文件：`bindings/translator-jni/src/lib.rs`

- `Entry` 增加自己的 `generation`；`Registry` 的全局 `generation` 只用于生成唯一句柄，不再用于淘汰其它存活实例。
- `Registry::insert`：`index` 单调、永不复用；返回 `"generation:index"`；同时存活上限 **1024**，超限返回 `OutOfBudget`。
- `Registry::resolve`：校验格式 → 查 index → 校验**该 Entry 的** generation → 校验 closed；旧实例不会因新实例创建而失效。
- `Registry::close`：只有 generation 匹配才删除；错误 gen 不会误伤别的实例；删除时置 closed。
- `nativeCall` / `nativeClose` 改用上述方法；`capabilities` 增加 `binding: { multi_instance: true, max_instances: 1024 }`。
- 保持 JNI v1：四个导出符号、`"gen:index"` 形状、JSON 信封、12 个业务错误码不变。

### 1.2 P8.2 共享 Bergamot 引擎/worker 与 ORT 会话

文件：`crates/translator-nmt-bergamot/src/lib.rs`、`crates/translator-api/src/lib.rs`

- 新增 `BergamotNmtEngine::shared(config) -> Result<Arc<Self>, TranslationError>`。
- 进程内静态池只存 **`Weak`**：最后一个 `Translator` 释放后引擎自然 drop，worker 随 `ProcessTransport::drop` 终止；池不会永久钉住模型。
- 池键覆盖：worker/native/model/snapshot 路径、**五个模型文件的 role+sha256**、source/target、cpu_threads、beam、protection、runtime_build、request_timeout、cache_capacity、idle_ttl。同一 `id@version` 但 tokenizer/词表/短名单内容变化不会误共享。
- `TranslatorBuilder::nmt_bergamot` 改用 `shared`；相同模型/配置的多个 `Translator` 共享同一个 engine、`load_gate`、`PlanCache` 与 worker。
- `BergamotNmtEngine::new` 仍保持独立构造（显式不共享），避免破坏需要隔离的调用方。
- ORT 同样提供 `OrtNmtEngine::shared`：键为 canonical model_dir + 三文件内容哈希 + source/target/threads/max_new_tokens/protection/steady_bytes/decode_policy；`TranslatorBuilder::nmt_ort` 改用 shared。ORT 池同样只存 `Weak`，最后一个实例释放后会话/arena 释放。
- 池不会跨进程共享；不同 `snapshot_root` 也不共享（配置差异必须显式）。

测试（`crates/translator-api/tests/shared_engine.rs` 4 条 + `shared_engine_ort.rs` 3 条，全 PASS）：

| 用例 | 验证 |
|---|---|
| `sm01_相同配置拿到同一个引擎与worker` | 两个 builder 的 `Arc` 指针相同 |
| `sm02_关闭一个实例不影响另一个` | drop A 后 B 仍持有引擎 |
| `sm04_不同模型内容或解码参数不得误共享` | 不同模型内容/beam 得到不同 `Arc` |
| `sm03_最后一个实例释放后池不持有强引用` | 最后一个实例 drop 后 `Weak::upgrade() == None` |
| `sm01_ort_相同配置共享同一个会话` / `sm04_ort_不同解码配置不误共享` / `sm03_ort_最后一个实例释放后池只留弱引用` | ORT 同样共享/隔离/可回收 |

边界：本测试用假模型文件验证"共享/不共享"的构造语义，不启动真实 native 模型；真实 worker 的加载次数/内存需在 P10.1 的真实模型实验中补测。

共享后的**故障/生命周期域**（必须在宿主文档里写清）：

- 共享引擎是**共享故障域**：任一实例的 `unload_nmt` / `evict_idle` / 取消导致的 worker 终止会影响所有共享该引擎的 Translator；
  宿主若要隔离故障，应显式用 `BergamotNmtEngine::new` + `builder.engine` 构造独立实例，而不是 `shared`。
- `Translator::clear_cache()` 只清协调器缓存，不清共享引擎的 `PlanCache`；后者以 plan digest 为键，模型/解码不变时复用是安全的。
- 共享引擎的每 Translator 内存预算仍按 358 MiB 下界各自记账（P8-D06），不表示进程真实 RSS。

### 1.3 P8.3 执行计划与缓存一致性

文件：`crates/translator-core/src/{cache.rs,coordinator.rs}`、`crates/translator-plugin-api/src/lib.rs`、`crates/translator-nmt-{bergamot,ort}/src/lib.rs`、`crates/translator-dictionary/src/lib.rs`、`crates/translator-api/src/lib.rs`

- `TranslationEngine` 新增默认方法 `cache_identity() -> Option<String>`；不实现的后端保持 `None`（完全向后兼容）。
- `CacheKey` 新增 `engine_cache_identity: Option<String>`；Coordinator 在建键时调用 `engine.cache_identity()`。
- Bergamot：构造期计算 `static_cache_identity`，字段与 `ResolvedExecutionPlan` 一致（engine/runtime/build/model_revision/五文件摘要/语言/beam/threads/protection/rules/glossary/pipeline/privacy），用 `plan.digest()` 作为身份。
- ORT：首次 `cache_identity()` 时用 `revision_of()`（encoder+decoder+tokenizer 内容哈希）+ threads/max_new_tokens/protection/decode_policy 计算身份，并缓存。
- 词典：`DictionaryManifest::content_digest()` 对 `id@version` + 逐文件 sha256 做稳定摘要；`TranslatorBuilder` 的资源指纹改为 `id@version#content_digest`（同版本重打包不再复用旧译文）。
- 隐私域：`CacheKey.privacy_domain` 对 `RemoteOnly` 与本地策略分开（`remote` / `local`），至少防止远程与本地结果共享缓存。

## 3. 与设计的偏差及原因

| 编号 | 偏差 | 原因/影响 |
|---|---|---|
| P8-D01 | P8.2 只做**进程内**共享，不做跨进程/共享内存 | 跨进程共享 native 模型需要新的协议与生命周期，超出 P8；同进程多 Translator 已受益 |
| P8-D02 | 池只存 `Weak`，不保活空闲模型 | 避免"池把模型钉死"；空闲回收仍由宿主/TTL 决定 |
| P8-D03 | 共享测试用假模型文件，不启动真实 Bergamot | 真实模型需许可权重与 native；SM-01 的 `Arc` 共享已证明 worker 复用，真实加载次数留 P10.1 |
| P8-D04 | EP-02 规则/术语只做 id@version，未做文件内容摘要 | 避免改动规则/术语资源身份格式；当前版本号契约要求"改内容必须改版本" |
| P8-D05 | EP-04 只有 RemoteOnly/本地二元隔离 | 公共 `TranslateRequest` 无宿主隐私域字段；新增字段会破坏结构体字面量，留 P9/P11 |
| P8-D06 | 共享引擎的每 Translator 内存预算仍各自按 358 MiB 下界记账 | 预算按实例下限估计，不声称等于真实进程 RSS；P10.1 再校准 |
| P8-D07 | JNI 同时存活上限 1024，超限 `OutOfBudget` | 防止句柄泄漏耗尽内存；未做 LRU 驱逐（宿主必须 close） |
