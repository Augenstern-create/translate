## 2. 实现的语义闭环

### 2.1 MeaningFrame

`MeaningFrame` 保存：

- `predicate`：谓词/形容词及来源 span、目标中文；
- `agent` / `patient`：实体、限定词、形容词、量词、span；
- `complement`：嵌入式谓词（want to **go**）；
- `modifiers`：时间等修饰；
- `polarity`：肯定/否定；
- `tense_aspect`：Simple/Past/Progressive/Imperative/Modal；
- `question`：None/YesNo/Wh；
- `source_spans`：来源证据。

第一版没有假装完整语义图：它只覆盖当前已验证结构。没有可靠角色的输入拒绝。

### 2.2 局部分析范围

已接入：

1. **并列祈使**
   - `Please open the door and close the window.`
   - 两个独立 imperative frame，Realizer 合并；
2. **否定 want-to**
   - `I don't want to go.`
   - 否定作用域在 `want`，不是 `to go`；
3. **过去动作 + 时间状语**
   - `She bought a new phone yesterday.`
   - 生成两个合法中文语序候选；
4. **固定颜色定语 + be 形容词**
   - `The light blue bag is heavy.`
   - `light blue` 作为固定颜色短语，不拆成 light/blue。

### 2.3 拒绝原因

保留内部 Trace：

- `UnsupportedClause`
- `PpAttachmentAmbiguous`
- `EmbeddedClause`
- `UnresolvedPronoun`
- `UnknownWord`
- `IncompleteCoverage`
- `UnsupportedPattern`

当前策略：

- `I saw the man with a telescope.` → `PpAttachmentAmbiguous`，NMT；
- `He didn't say she stole it.` → `UnresolvedPronoun`/嵌入从句证据，NMT；
- `If the server fails, restart it.` → 未解决代词，NMT；
- 词典证据不足 → 不生成 frame，NMT。

## 3. ChineseRealizer

第一版 `ChineseRealizer` 负责：

- 简单主谓宾语序；
- 并列祈使连接（请…，并…）；
- 名词短语：
  - `a new phone` → 一部新手机；
  - `the light blue bag` → 浅蓝色的包；
- 量词（来自 P19 词表数据）；
- 过去动作 + 时间：
  - `她昨天买了一部新手机。`
  - `昨天她买了一部新手机。`
- 否定 want-to：`我不想去。`
- be 形容词：`浅蓝色的包很重。`

输出不是单一字符串：

```rust
RealizationCandidate { text, rule_id, rank }
```

`CandidateSelector` 只做确定性 rank（不是中文语言模型分数），当前优先
subject-first 语序，同时保留 time-first 候选用于测试/后续选择。

**未实现**：完整“的/地/得”、全部体貌、所有否定范围、复杂修饰、所有量词、
通用中文自然度排序。

## 4. 与 Coordinator/Planner 的集成

新增配置：

- `CoordinatorConfig.semantic_composer: Option<Arc<SemanticCompositionEngine>>`
- `TranslatorBuilder::semantic_composition_file(...)`
- `TranslatorBuilder::semantic_composition(...)`

执行顺序：

1. 固定模板（P16-R）；
2. P20-C 语义组合（仅 Sentence + AutoLocalFirst/DictionaryOnly）；
3. P19-G CompositionEngine（同上）；
4. 原 Planner：Dictionary / Local NMT / Remote（按策略与授权）；
5. 术语/质量/缓存/Trace 统一收尾。

P20 语义结果使用：

- `TranslationRoute::Rule`；
- `engine_id = semantic:<id>`；
- 缓存键含语义规则版本与内容指纹；
- `LanguageEvidence` 完整覆盖证据；
- `UnitExecutionTrace`；
- 与 NMT 共用质量检查。

`LocalOnly` / `RemoteOnly` 仍不被规则旁路。

## 10. 明确未完成

1. **不是通用语义解析器**：只有 4 类新增高级结构。
2. **不覆盖 P19 全部句型**：语义层只接管新结构；旧 36 正例仍走 P19。
3. **没有完整 ChineseRealizer**：的/地/得、全部体貌、全部否定范围、复杂修饰、
   所有量词未实现。
4. **没有中文 LM 排序**：CandidateSelector 是确定性 rank，不是自然度模型。
5. **没有默认切换**：P20 语义路径 opt-in；需要更大独立集和人工评审后才考虑默认。
6. **人工评审仍 PENDING_HUMAN**。
7. **P19 的 36 条规则与 P20 的 7 条对抗集均为项目自编**，不能冒充外部盲评。

## 11. 结论

P20-C 第一版完成了“局部语义帧 → 独立中文生成 → 候选选择 → 统一 Coordinator”
的核心闭环，并用独立对抗集证明：

- P19-G 无法处理的 4 条高级结构可以由新层可靠生成；
- 3 条歧义/嵌套/指代反例没有被规则错误接管；
- 320 与文档集无退化；
- 规则/缓存/策略/质量仍走 P17-A 统一链。

但结论保持 **Conditional**：能力窄、样本小、人工评审未完成，语义路径尚未默认。
下一阶段应继续：

1. 扩充 MeaningFrame 的角色/作用域；
2. 让 ChineseRealizer 覆盖更多中文表层现象；
3. 用真实未覆盖数据建立独立对抗集；
4. 完成 P19/P20 人工盲评后再决定默认采用范围。
