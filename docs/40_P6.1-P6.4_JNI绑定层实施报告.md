## 1. 实际实现内容

### 1.1 新增 `bindings/translator-jni`（cdylib + rlib）

| 文件 | 内容 |
|---|---|
| `bindings/translator-jni/Cargo.toml` | `crate-type = ["cdylib","rlib"]`；依赖 `translator-api`（`mocks/dictionary/rules/resource`）、`translator-types`、`translator-resource`、`serde_json`、`pollster`、`jni 0.21`；透传 feature `nmt-bergamot`/`nmt-ort`（默认都不开） |
| `bindings/translator-jni/src/lib.rs` | 契约 v1 的四个导出符号 + 句柄注册表 + 错误信封 + 4 条单测 |

**关键实现点**（都能在源码里对上）：

- **句柄**：`Registry { generation, next_index, entries: HashMap<u64, Arc<Entry>> }`，句柄是 `"gen:index"`。
  `nativeCall` 在锁内只做"校验代际 + `Arc::clone`"，**锁外**执行 SDK 调用（`docs/38` §4 要求）。
- **并发关闭语义**（用户明确要求）：`nativeClose` 先把 `closed` 置位、再从表里移除；在飞请求手里已有
  `Arc`，所以 `Translator` 直到最后一个 `Arc` 释放才 drop。新请求看到 `closed`/表里没有 → `AlreadyClosed`。
  关闭回包里带 `inflight_kept` 字段（关闭时是否还有别的 `Arc` 持有），便于观测。
- **`panic` 边界**：`guarded_call` 用 `catch_unwind(AssertUnwindSafe(...))` 包住整个入口，
  panic → `BackendFailed` + "native panic：已在 JNI 边界拦截"。
- **编码**：输入用 `env.get_string` 读；含 `\0` 直接 `InvalidRequest`；输出用 `env.new_string`（内部
  `NewString` UTF-16），不用 `NewStringUTF`。
- **能力如实报告**：`capabilities` 返回 `runtimes` 数组，`runtime.bergamot` / `runtime.ort` 在 Android 上
  都是 `available:false, reason:"not_compiled"`——不谎报未编译进来的后端。
- **mock 引擎**：只有 config 里显式 `"mock_engines": true` 才注册（`MockNmtEngine`/`MockRemoteEngine(false)`/
  `MockDictionaryProvider`），默认产物里没有"假翻译"。

> `J-06` 的语义值得单独说明：worker 线程连续 400 次 `lookup`，主线程在 60 ms 后关闭句柄。结果

## 4. 偏差、跳过与原因（必须明写，不得当 PASS）

- **D-136：用 `d8 + app_process` 而不是 APK/Instrumentation。**
  按 `docs/39` D-134：Gradle 会写 `~/.gradle`（工作区外）。本轮所有宿主侧写入都在仓库内
  （`tests/android-harness/out/`），模拟器侧只在 `/data/local/tmp/p6`。
  **代价**：这验证的是 JNI 契约与 SDK 行为，**不是** Android 应用生命周期（Activity/Service 启动、APK 安装、
  权限模型）。这条限制必须在 P6 结论里保留。
- **D-137：J-07/J-14/J-15 未做。**
  原因：J-07 需要先构造"损坏资源包 + 仓库"的夹具并走 `resource_repo` 路径；J-14 需要采集 `/proc/<pid>` RSS
  与首/热调用时延（模拟器口径）；J-15 需要重复装卸 `.so`。三者都属于"再加一小时"的量，本轮按优先级让位给
  J-01～J-13 的闭环。**没有**把它们算进 PASS（见 §3 表格）。
- **D-138：J-12（Windows 回归）本轮未跑。**
  原因：JNI crate 已在 Linux 侧随 workspace 跑过 `fmt/clippy/test`（379 passed），但 **Windows 工作区
  `E:\augenstern\translate` 还没同步这批改动**。同步需要在 Windows 侧 `git fetch + ff-merge` 再跑
  `cargo test --workspace`，属 P6.4 的剩余动作；本轮未执行，故 J-12 = pending。
- **D-139：`jni 0.21` 是新依赖（供应链 +1）。**
  许可证 `MIT OR Apache-2.0` 合规；`licenses/third-party.json` 已重算为 172 包。若后续要求"零新增依赖"，
  替代方案是手写 JNI 函数表偏移（风险更高，未采用）。
- **D-140：`capabilities` 的 `runtimes` 字段是新增的 DTO 约定。**
  `docs/39` §1.3 只规定了 `engines`；本轮加了 `runtimes [{id,available,reason}]`，用于"未编译的 NMT 必须
  如实报告"（J-01c/J-09）。属**契约增量**，需要同步回 `docs/39` 的 DTO 样例（本轮已在 `docs/41` 记录）。
