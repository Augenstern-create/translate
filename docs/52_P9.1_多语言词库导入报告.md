## 2. 导入实现

### 2.1 统一链路

```text
Kaikki JSONL ──> import_kaikki.py ──> normalized JSONL ─┐
JMdict XML   ──> import_jmdict.py  ──> normalized JSONL ─┼─> pack-dictionary --format jsonl
                                                         └─> FST + SQLite v2 + manifest
                                                              └─> ResourceStore / Translator.lookup
```

- 复用现有 `DictionaryEngine`/`DictionaryProvider`/FST/SQLite v2；没有第二套运行时查词引擎。
- `pack-dictionary` 新增 `--format jsonl`、`--license-file` 与 `parse_jsonl`；`RawEntry` 仍是现有类型。
- **修复同音词合并 bug**：`traditional`/读音键不再用于合并记录；否则 はし 的 橋/箸/端 词义会混在一起。
  单值 FST 仍只能让 `はし` 指向一条；同音多义完整表达需要后续 schema 扩展（记为 P9 偏差）。
- 词典插件 id 改为包级唯一（`dictionary.package:<manifest.id>`），否则两个词典包无法同时注册
  （DI-04 必需）；单包旧行为在语义上不变，但 `engine_id` 字符串带包 id。
- `p33-bench dictionary` 新增 `--term` / `--lang`，用于 P9 样本基准；默认值不变。

### 4.1 质量门判断

- 950 条 en→zh 样本**全部**有中文释义（导入器按 CJK 过滤），不存在"大量没有真正中文释义"的情况；
- 但指定 10 个多义词只覆盖 2 个（light/close），**不能据此宣布完整高质量 en→zh 主词典**；
- 结论：**不进入全量阶段**。若要覆盖 bank/spring 等，需要：
  1) 批准更大的 Kaikki 下载额度或定向 sample；或
  2) 选择另一个含目标词的公开英文词头→中文释义数据集；
  3) 再跑 DI-01/质量抽检。
