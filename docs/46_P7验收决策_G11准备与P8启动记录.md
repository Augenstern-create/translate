## 2. G12：维持"不随 SDK 分发权重"

### 2.1 决策

- 保留当前 Mozilla Marian 技术路线，**不立即更换模型**；避免转换、质量评估与回归成本。
- 权重不进入 Git 仓库、SDK 发行包、CI 工件、镜像或缓存上传。
- 保留 `fixtures/nmt/models.lock.json` 的来源/版本/SHA-256/许可状态；`licenses/model-assets.json` 继续 `status=pending`、`redistribution=prohibited-until-confirmed`。
- 正式公开发行前，要么取得书面再分发授权，要么替换为许可明确的权重。
- **G12 保持 open**；`check-release.py --release-mode` 继续 FAIL；本轮未改任何门禁条件。

### 2.2 需要记住的边界

用户明确提示：**"让用户自行下载也不自动解决所有授权问题，仍需遵守模型及下载来源的使用条款。"**
因此 README / 发行说明只能写"SDK 不代下载、不代分发"，不能写成"已解决许可"。
G12 的关闭条件仍是有效的授权文本 + 审核记录，或改用明确许可的替代模型。

## 5. P8 P0：JNI 多实例（ADR-063，Proposed）

### 5.1 问题

`docs/44` D-156 记录：`nativeCreate` 推进全局 generation，创建第二个 Translator 会让第一个句柄立即 `AlreadyClosed`。
对通用跨平台 SDK，这是不应长期保留的限制；它比 J-15c（`.so` 卸载，ART 限制）更值得优先修复。

### 5.2 方向（ADR-063）

- handle 仍为 `"gen:index"`；`index` 单调、永不复用；
- 每个 `Entry` 保存自己的 `generation` 与 `closed`；
- `nativeCall` 校验 `entry.generation == handle.gen && !closed`，不再比较全局 generation；
- `nativeClose` 只关闭 index 对应的 entry；已关闭/伪造 handle 仍 `AlreadyClosed`；
- `capabilities` 增加 `binding.multi_instance=true` 供宿主探测；`protocol_version` 保持 1；
- 四个导出入口、JSON DTO、12 个业务错误码不变。

### 5.3 交付顺序（P8）

1. 先补合同测试（多实例 interleave、close A 不影响 B、index 不复用、并发 create/call/close）；
2. 再改注册表；确保旧单实例行为不回退；
3. Android Harness 增加 `M-01..M-06`，跑模拟器；
4. 更新 `docs/40`/`docs/41` 的 P6 语义说明，避免"旧代际一律失效"与新实现冲突。

本轮只写 ADR，**未改代码**；P8 开工时按上面顺序执行。

**P8-AUDIT 结果（2026-11-07，`docs/48`）**：P8.1 多实例当时为 **Confirmed missing**（源码确认全局 generation 会作废旧句柄）；
P8.2 共享模型/P8.3 计划缓存为 **Partial**；P9/P10/P11 的大功能多数为 **Confirmed missing**。审计未改功能代码，
现有回归 391 passed / 0 failed / 60 ignored。P8.1 实施仍以"先写 M-01～M-06 失败测试"为第一步。

**P8 已完成（2026-11-07，`docs/49`）**：ADR-063 已 Accepted；JNI per-entry generation/closed 实现，Android M-01～M-06 与 P6 回归 **40 PASS / 0 FAIL / 1 PENDING**；Bergamot 共享池、`cache_identity`/词典内容摘要/远程-本地缓存域已接入；Linux **401 passed / 0 failed / 60 ignored**。G12/G11 仍 open。

### 5.4 P8 合同测试矩阵（建议）

| ID | 场景 | 期望 |
|---|---|---|
| M-01 | 连续 `nativeCreate` A、B，两个 handle 都不关闭 | A/B 均可调用；B 的创建不再让 A 失效 |
| M-02 | A/B 交替 `lookup` / `translate` | 各自结果正确，不串实例 |
| M-03 | `nativeClose(A)` 后调用 A、再调用 B | A=`AlreadyClosed`；B 正常 |
| M-04 | 关闭 A 后创建 C，再调用 A/B/C | A=`AlreadyClosed`；B/C 正常；A 的 index 不被复用 |
| M-05 | 8 线程并发 create/call/close | 无崩溃、无 UAF；成功数 + `AlreadyClosed` = 总调用数 |
| M-06 | 伪造 `gen:index`（错误 gen / 不存在 index） | `AlreadyClosed` 或 `InvalidRequest`；不触碰真实实例 |

验收口径：M-01～M-06 全部 PASS 才能把 ADR-063 从 Proposed 改为 Accepted；在此之前 P6 的
"全局 generation 失效"仍是当前实现事实。
