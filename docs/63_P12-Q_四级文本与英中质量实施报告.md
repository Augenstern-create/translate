## 2. 四级文本架构

### 2.1 API

```rust
pub enum TextKind { Auto, Word, Sentence, Paragraph, Document }
pub enum ParagraphStrategy { Auto, Whole, Sentence, Group }
pub struct TranslateOptions {
    pub mode: TranslationMode,
    pub text_kind: TextKind,
    pub paragraph_strategy: ParagraphStrategy,
    pub strategy: Option<String>,
    pub context_id: Option<String>,
}
```

- `TranslatorBuilder::text_kind()` / `paragraph_strategy()` 设默认值。
- `Translator::translate_with_options()` / `translate_with_diagnostics_options()` 单请求覆盖。
- 旧的 `translate()` / `translate_with_mode()` 仍可用；`TranslateRequest` **没有新增字段**。
- CLI 增加 `--text-kind` / `--paragraph-strategy`。

### 2.2 自动分类

`translator-core::planner::analyze()` 依据句数、段落数、Markdown 结构、长度、代码块综合判断，**不只看长度**：

| 输入 | 分类 |
|---|---|
| `bank` | Word |
| `memory leak` | Word（词典精确命中） |
| `Please restart the server.` | Sentence |
| 2+ 句/2+ 段 | Paragraph |
| 标题/列表/代码块/6+ 句 | Document |

宿主显式指定的 `TextKind` 优先；无法可靠分类时默认 Sentence/Word 的保守路径，并记录 `text_kind` 诊断。

### 2.3 规划与执行

- Word/Sentence：单路径，仍走原 `TranslationEngine`。
- Paragraph：
  - `Whole`：整段一次 NMT（上下文完整，有截断风险）。
  - `Sentence`：逐句 NMT，按原顺序/分隔符拼接。
  - `Group`：每 2 句一组。
  - `Auto`：1–2 句整段，≥3 句逐句（由 50 段对照决定）。
- Document：Markdown/纯文本分块；标题/列表/引用只翻译内容并恢复前缀；代码块、表格行原样保留；段落失败保留原文并加 `SegmentFailed` 警告。
- 单句长句在**唯一** `and/but` 且第二段像谓语/主语从句时切分；多连接词/分词短语不切，避免丢主语。

### 2.4 缓存身份

`CacheKey` 新增：`text_kind`、`strategy`、`context_fingerprint`。模式/类型/策略/上下文任一不同都不共享缓存。
测试：`文本类型与策略进入缓存身份`、`上下文身份进入缓存键`。

## 4. W2 — Sentence 正确性

### 4.1 旧 4 条致命样本：4/4 不再致命

| ID | 原文 | P12 输出 | 处理 |
|---|---|---|---|
| en-zh-0151 | The CPU usage stayed below 50%. | CPU使用率保持在50%以下. | 百分比保护 + 范围词换位 |
| en-zh-0286 | The discount is 15% for orders over $100. | 折扣是15%超过100美元的订单 | 百分比保护 + 术语（订单） |
| en-zh-0296 | The error code is 0x80070005. | 错误代码是0x80070005. | 十六进制保护 + 标点修复 |
| en-zh-0309 | The event starts at 8 PM and ends at 11 PM. | 活动于下午8时开始，11点结束. | `and` 句级切分 |

数字保护只覆盖“丢失即错”的格式：百分比、十六进制、日期、版本号；**冒号时间不单独保护**（`10:30 AM on March 5` 会被拆坏，改为数字检查+自然翻译）。保护片段拼接时若两侧都是数字会插入空格，避免 `10:30` + `2026` 粘连。

### 4.2 320 条 P11 金样本（text_kind=Sentence）

| 配置 | chrF | BLEU | fatal | 数字保真 | 错误 |
|---|---:|---:|---:|---:|---:|
| P11 baseline | 0.4577 | 0.4546 | 4 | 0.8983 | 0 |
| P12 baseline（仅新保护/切分） | **0.4632** | **0.4607** | **0** | **1.0** | 0 |
| P12 full（+词典/规则/术语 Enforce） | **0.4659** | **0.4641** | **0** | **1.0** | 0 |

相对 P11：full **chrF +0.0082、BLEU +0.0095**；4 条 fatal 全部修复；回归 2 条、改善 15 条。回归只剩：`0.05%盐` 少了“的”、日期保护后句号变 ASCII（语义与数字均正确）；已把切分收紧为仅 and/but、仅单连接词、严格主语判断。

### 4.3 独立 100 句验证集

| 配置 | chrF | BLEU | fatal | 数字 |
|---|---:|---:|---:|---:|
| greedy（P11 路径） | 0.4466 | 0.4557 | 1 | 0.9556 |
| 新保护 + 句级切分 | **0.4535** | **0.4621** | **0** | **1.0** |

### 4.4 Beam Search（40 条长句/数字子集）

带 cache 的 beam：首步一次 decoder，后续每个 beam 只喂 `[last]`，延迟从“每候选全序列重跑”的 30× 降到：

| 配置 | chrF | BLEU | 延迟 | 相对贪心 |
|---|---:|---:|---:|---:|
| greedy | 0.4402 | 0.4658 | 15.7 s | 1× |
| beam 2 | 0.4624 | 0.4885 | 80.9 s | 5.4× |
| beam 4 | **0.4682** | **0.4974** | 217.3 s | 14.5× |

质量随 beam 提升，但延迟代价明显；**未设为 Precise 默认**，仅保留 `OrtNmtConfig::with_beam_width` / `quality-runner --beam` 作为可选实验。30,000 条长文本不应开 beam 4。

## 5. W3 — Paragraph

50 段（每段 3 句，来自已验证句对组合）A/B/C：

| 策略 | chrF | BLEU | 段落完整率 | fatal | 数字 |
|---|---:|---:|---:|---:|---:|
| A 整段 | 0.3917 | 0.4299 | 0.48 | 0 | 1.0 |
| B 逐句 | **0.3987** | **0.4493** | **0.58** | 0 | 1.0 |
| C 句群（2 句/组） | 0.3909 | 0.4294 | 0.50 | 1 | 0.6 |

结论：**B 逐句最好**；C 在长句组上会截断（Q-026）。Auto 策略改为 1–2 句整段（保留短段上下文）、≥3 句逐句；Group 仅保留为显式实验。
