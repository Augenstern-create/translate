### 2.1 为什么是 344 而不是 Linux 的 391

- Windows 上按平台语义排除的 Linux 专属目标（worker 进程边界、快照只读位、leases 存活探测、Bergamot 配置等）不计入；
- 本轮新增的 J-07 在 Windows 上跑 4 条（symlink 用例 `cfg(unix)` 不跑），JNI 输入边界单测 3 条照跑；
- **0 failed**，没有用 `--skip` 或删除测试换绿。差值均为平台门禁，逐条理由见 `P7-test-default.txt` 的 `Running ...` 段。

### 2.2 G08 在 Windows 上的语义

`crash_point()` 在 Windows 上没有 `SIGKILL`；测试父进程用 `Child::kill()`（`TerminateProcess`）作为"外部强制终止"的等价路径，并断言子进程**非正常退出**。5 个安装关键点的 `recover()` / `audit()` / 旧版本校验断言与 Linux 相同。因此：

- **Windows：外部强制终止语义 PASS**；
- **Linux：外部 `SIGKILL`（signal=9）PASS**（`docs/44` §2.5）；
- 两者都保留各自平台证据，不互相替代。

### 2.3 ORT 与缓存路径

- ORT 的预编译缓存实际落在 `E:\augenstern\translate\.build\ort-cache\dfbin`（`ORT_CACHE_ENTRIES=dfbin`）。
- `%LOCALAPPDATA%\ort.pyke.io` 的 `LastWriteTime` 为 **2026-11-06 17:23:54**，本轮未变化；证明本轮没有向工作区外写 ORT 缓存。
- 24 个 ORT 用例（13 合同 + 6 真实模型 + 5 门面）全部通过，说明 Windows 的 DirectML 静态变体在本机可用；这不改变"Windows 与 Linux CPU 变体不做绝对速度倍数比较"的口径（ADR-052）。
- 没有下载新模型：`P4_ORT_MODEL_DIR` 指向既有 `.build\model-cache\ort-model`。
