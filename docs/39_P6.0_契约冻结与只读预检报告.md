### 1.2 `translator-api` 对外面（契约的"上游"必须钉死）

**构造**：`Translator::builder()` → `dictionary_package` / `dictionary_from_store` / `rules` / `rules_file` /
`term_guard` / `term_table_file` / `term_policy` / `memory_budget` / `limits` / `cache_capacity` /
`strict_placeholder_restore` / `engine` / `provider` / `backend` / `nmt_bergamot` / `nmt_ort` → `build()`。

**调用**（`&self`，`Translator: Send + Sync`）：

| 方法 | 签名要点 | JNI 对应 |
|---|---|---|
| `translate(&TranslateRequest)` | `async fn` → `Result<TranslationResult, TranslationError>` | `nativeTranslate` |
| `translate_with_diagnostics` | `async fn` → `Result<TranslateOutput, _>` | v2（P6.2 起） |
| `lookup(&LookupRequest)` | `async fn` → `Result<Vec<DictionaryEntry>, _>` | `nativeLookup` |
| `detect_language(&str)` | `async fn` → `Result<Vec<LanguageGuess>, _>`；空串返回 `InvalidRequest` | `nativeDetect` |
| `capabilities()` | 同步 → `Vec<CapabilityInfo>` | `nativeCapabilities` |
| `explain_route` / `explain_rules` / `explain_terms` | 同步 | v2 |
| `memory_report()` / `nmt_states()` / `nmt_cache_stats()` | 同步 | v2（J-14 用） |
| `shutdown()` | `async` | `nativeClose` 的内部实现 |
| `clear_cache` / `evict_idle_nmt` / `unload_nmt` / `unload_nmt_ort` | 同步 | v2 |

**feature（编译开关矩阵）**：`mocks` / `dictionary` / `rules` / `resource` / `nmt-bergamot` / `nmt-ort` /
`nmt-ort-runtime`；`default = []`。→ **JNI crate 默认只开 `mocks + dictionary + rules + resource`**，
NMT 一律不默认开（Android 上没有已验证的 NMT 后端，见 §3 J-09）。

**错误码（12 个，`TranslationErrorCode`）**：`InvalidRequest`、`UnsupportedLanguage`、`ResourceNotInstalled`、
`CapabilityUnavailable`、`RuntimeInitFailed`、`OutOfBudget`、`Cancelled`、`Timeout`、`BackendFailed`、
`NetworkNotAuthorized`、`ProviderRejected`、`IntegrityFailure`。→ JNI 侧**不新增错误码**，只做透传 + 稳定字符串。

### 1.3 契约 v1（**冻结**）

**类与入口**（包名固定，避免后续重命名破坏 ABI）：

```text
ai.ridge.translator.NativeBridge   （class，全部 static native）
  nativeProtocolVersion() -> jint                       // = 1
  nativeCreate(String configJson) -> jstring            // 返回 {"ok":true,"handle":"..."} 或 {"ok":false,"error":{...}}
  nativeCall(String handle, String method, String payloadJson) -> jstring
  nativeClose(String handle) -> jstring
```

- 只保留 **四个** native 方法：创建、调用、关闭、版本。方法级 API 全部走 `nativeCall(method, payload)`，
  这样新增能力（translate/detect/…）**不需要改 ABI**，也让"未知方法"能返回稳定错误而不是 `UnsatisfiedLink`.
- `method` 取值 v1 固定四个：`capabilities`、`detect`、`lookup`、`resources`；`translate` 在 P6.2 加入。

**句柄方案**（P0）：

- 句柄是 `String`（不是 `jlong`）：`"{generation}:{index}"`，例如 `"7:3"`。
  理由：`jlong` 一旦被宿主误当指针传递，错误会变成段错误；字符串句柄在 JNI 层做**查表 + 代际校验**，
  过期句柄返回 `AlreadyClosed`，不可能解引用任意内存。
- 注册表：`Mutex<HashMap<u64 /*index*/, Entry>>` + 单调 `generation`；`Entry { translator: Arc<Translator>,
  closed: AtomicBool }`。`close` 先原子置位再移除；**持锁区只做查表**，`Arc` 复制出来后才在锁外调用 SDK
  （对应 `docs/38` §4 的"不得持锁做 I/O/推理"）。
- 同一句柄并发 `close` → 第一个成功、其余返回 `{"ok":true,"already_closed":true}`（幂等）。

**DTO 协议 v1**：JSON（UTF-8），显式 `"protocol_version": 1`；未知 major 直接 `InvalidRequest`。

```json
// create 的 config
{"protocol_version":1,
 "data_dir":"/data/user/0/ai.ridge.translator/files",
 "cache_dir":"/data/user/0/ai.ridge.translator/cache",
 "dict_package":null,          // 可选：词典包目录（绝对路径）
 "rules_file":null,            // 可选：规则 JSON
 "memory_budget_bytes":null,   // 可选：默认由 core 决定
 "term_policy":"warn"}         // off|warn|enforce

// capabilities 的返回
{"protocol_version":1,"platform":"android-x86_64",
 "engines":[{"engine_id":"mock.nmt","capabilities":["translation.nmt"],"priority":50,"license":"MIT"}],
 "runtimes":[{"id":"runtime.bergamot","available":false,"reason":"platform_not_validated"}]}

// detect / lookup / resources 统一形状
{"protocol_version":1,"ok":true,"data":{...}}
{"protocol_version":1,"ok":false,"error":{"code":"InvalidRequest","message":"文本为空"}}
```

**错误映射**：SDK 的 `TranslationError { code, message, suggested_packages }` → JSON
`{"code": code.as_str(), "message": message, "suggested_packages": [...]}`；JNI 层**不抛业务异常**，
只有"契约级错误"（坏 JSON、未知方法、句柄格式非法）才抛 `IllegalArgumentException`。
`panic!` 一律在 FFI 边界 `catch_unwind` 兜住并转成 `BackendFailed` + `native panic` 标记。

**编码规则**（P1，JVM Modified UTF-8 的坑）：

- JNI 侧用 `GetStringUTFChars` 拿到的是 **Modified UTF-8**（`\u0000` 编码为 `C0 80`，补充平面用代理对）。
- 契约 v1 明确：**输入文本不得含 `U+0000`**；检测到原样 `\0` 或 `C0 80` 一律返回 `InvalidRequest("文本含 NUL")`，
  不做静默替换。Emoji/非 BMP 必须正确往返（J-02 会验）。
- 输出统一用 `NewStringUTF`？**不用**——改用 `NewString(UTF-16)`：Rust 侧把 `String` 转 `Vec<u16>`，
  避免把 Rust 的 UTF-8 硬塞进 Modified UTF-8 的坑。

**线程模型**：native 入口是**阻塞**的（内部 `pollster::block_on`），契约要求宿主在后台线程调用；
JNI 层**不缓存 `JNIEnv`**，不跨线程持有局部引用；不做全局引用（v1 不回调 Java）。

## 3. 与原设计的偏差及原因

- **D-130：句柄从计划里的"`long handle`"改成"字符串句柄 `generation:index`"。**
  原因：`docs/38` §3.1 建议 `long handle` 作不透明 ID，但 `jlong` 在 Kotlin 侧极易被误当指针/被复制到
  另一进程；字符串句柄能强制走查表，过期即 `AlreadyClosed`。代价：多一次 JSON 字段解析（可忽略）。
- **D-131：native 方法从"每个能力一个"收敛为 4 个（`create`/`call`/`close`/`protocolVersion`）。**
  原因：方法级 API 走 `nativeCall(method, payload)` 后，**新增能力不改 ABI**；同时"未知方法"能返回结构化错误，
  而不是 `UnsatisfiedLinkError`（后者在真机上极难定位）。代价：多一层字符串分发（微秒级）。
- **D-132：输出不用 `NewStringUTF`，改用 `NewString(UTF-16)`。**
  原因：`NewStringUTF` 期待 Modified UTF-8，Rust 的 `String` 是标准 UTF-8；含 Emoji（非 BMP）时两者不一致，
  会出现"JNI 侧看到乱码/截断"这类最难查的问题。代价：Rust 侧多做一次 UTF-16 转换。
- **D-133：契约规定输入不得含 `U+0000`，检测到即 `InvalidRequest`。**
  原因：Modified UTF-8 用 `C0 80` 表示 NUL，若静默转换，用户文本会被悄悄改写。影响：J-02/J-10 会各测一条。
- **D-134：JNI 验证载体选 `d8 + app_process`，暂不做 Gradle/APK Instrumentation。**
  原因：Gradle 会把依赖与缓存写到 `%USERPROFILE%\.gradle`（Windows）或 `~/.gradle`（Linux），属工作区外写入，
  按 ADR-057 需逐项审批；`d8 + app_process` 只需 `cmdline-tools`（已存在）与模拟器内的 `/data/local/tmp`，
  全程不碰宿主机工作区外目录。代价：不是"标准 Android 测试"，**这一点必须在 P6.3 报告里写明**
  （它验证的是 JNI 契约与 SDK 行为，不是 Android 应用生命周期）。
- **D-135：P6 的 JNI 开发在 Linux 主机做，Windows 侧只做回归（J-12）。**
  原因：NDK/AVD 在 Linux 机（`docs/36`）；Windows 上按 `docs/32` §4.2 明确"不在 Windows 装 NDK"。
  影响：JNI crate 的源码在仓库（两端同一份），但"能编能跑"的编译发生在 Linux；Windows 只跑
  `cargo test --workspace` 的回归。
