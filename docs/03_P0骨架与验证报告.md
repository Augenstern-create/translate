## 3. 已落实的设计要求

### 3.1 依赖方向（§2「总体架构与依赖规则」）

```text
translator-types ← translator-plugin-api ← translator-core ← translator-api ← CLI
```

单向依赖，无环。`translator-types` **零外部依赖**，`translator-plugin-api` 只依赖 `translator-types`。
`Coordinator` 不认识任何具体引擎，因此替换后端不需要改核心代码（§5.4「替换演练」的前提）。

### 3.2 三套插件契约（§5.1）

| Trait | 用途 | 关键设计 |
|---|---|---|
| `TranslationEngine` | 词典 / NMT / 远程三类引擎 | `descriptor()` + `supports()` + `translate()` |
| `DictionaryProvider` | 查词，与翻译分离 | ADR-003：不得把词典单义强行覆盖语境 |
| `InferenceBackend` | Bergamot / ncnn / ORT | `supports_model()` 返回 `CompatibilityReport` |
| `LoadedModel` | 已加载模型句柄 | 注释明确警示原生句柄未必 `Sync`，不得硬塞 `Arc` |

### 3.3 路由规则（§6）

`AutoLocalFirst` 的实际行为（全部有测试覆盖）：

| 输入形态 | 选择 | 理由 |
|---|---|---|
| 单词（无空白、≤32 字符、无句末标点） | 词典 | 避免用词条释义冒充整句翻译 |
| 单词但词典不支持该语言对 | NMT | 退化并记录原因 |
| 单词且词典**未命中** | 词典 → **自动回退 NMT** | 仅在 `AutoLocalFirst` 下回退 |
| 短语 / 句子 | NMT | — |
| `LocalOnly` / `RemoteOnly` / `DictionaryOnly` | 严格按策略 | 不回退、不静默换引擎 |
| `ExplicitEngine(id)` | 指定引擎 | 不存在则报 `CapabilityUnavailable` |

**远程默认关闭**（ADR-004）：`RemoteOnly` 且宿主未授权时返回 `NetworkNotAuthorized`，
`AutoLocalFirst` **永不**自动走到远程。

### 3.4 流水线（§6）

已实现的完整链路：

```text
校验 → 规范化 → 语言识别（启发式）→ 占位符保护 → 路由 → 缓存查询
     → 执行 → 占位符还原（含丢失检测）→ 元信息补全 → 写缓存
```

其中两点值得强调：

- **占位符保护**覆盖 URL、`{占位符}`、`` `code` ``。还原失败会产出
  `TranslationWarning::PlaceholderRestoreFailed` 并列出丢失片段，**绝不静默**。
- **缓存键**包含：文本哈希、源/目标语言、引擎 id、术语表 id、规则版本、解码配置、隐私域。
  有测试验证"不同引擎不共享缓存""不同术语表不共享缓存"。

### 3.5 错误模型（§4）

12 个错误码与设计文档 §4 完全一致，未增删。
`TranslationError` 带 `suggested_packages`，未安装资源时可直接引导用户（测试覆盖）。

### 3.6 插件注册（§5.2）

- 校验插件 API **主版本一致**（`PluginApiVersion::accepts`）
- 拒绝重复 id（测试覆盖）
- `priority` 仅在可兼容插件间排序，按 `priority` 降序 + `id` 升序保证结果稳定

## 4. 实现中的取舍（诚实记录）

| # | 取舍 | 原因 | 后续 |
|---|---|---|---|
| 1 | 语言识别用**字符系统启发式**，非 fastText | P0 不引入模型；fastText 属 P1 | P1 接 `lid.176.ftz` |
| 2 | 缓存键中 `model_id` 暂为 `None` | 调用引擎前无法得知模型版本 | P2 改为「先解析模型、再算键」 |
| 3 | `timeout_ms` 字段已定义但**未生效** | 需要与执行器/取消机制一起设计 | P2 配合 `CancellationToken` 实现 |
| 4 | 并发预算 `ResourceLimits` 只有类型，未强制 | 属 P2 内存预算控制器 | P2 |
| 5 | Mock 引擎用 `[nmt en->zh-Hans] ...` 标记输出 | 避免冒充真实译文，便于肉眼确认路由 | 永久保留（测试专用） |
| 6 | CLI 手写参数解析，未引 clap | P0 控制依赖；解析代码 ~80 行 | 视需要替换 |
| 7 | `shutdown()` 目前只清缓存 | P0 无可释放资源 | P2 接租约与模型卸载 |

**唯一的外部依赖是 `pollster`（约 20 行代码的 `block_on`），且仅 CLI 使用。**
`translator-api` / `core` / `plugin-api` / `types` 四个 crate **零外部依赖**。

> 这一点直接满足「API 无重型依赖」。后续引入 tokio 时，应只作为可选 feature，
> 不得强制污染 `translator-api` 的默认依赖树。

## 6. 已知限制

1. **没有真实译文**。所有输出都带 `[nmt ...]` / `[remote ...]` 标记，这是刻意为之。
2. **没有真实的语言识别**。汉字文本会同时给出 `zh-Hans` 与 `ja` 两个候选，符合设计文档
   "不能作为唯一语言依据"的要求，但准确率不足以产品化。
3. **无资源管理**。`ResourceNotInstalled` 的 `suggested_packages` 目前是拼出来的字符串，
   还没有真实的资源包清单支撑。
4. **超时与取消未实现**。`timeout_ms` 字段被忽略，调用方不应依赖它。
5. **未做 `unsafe` 审计**。P0 无 FFI，全是安全代码；引入 native runtime 后需补。

## 7. 建议的 P1 范围

按设计文档 §13，P1 是「字典/规则」，验收成果为"可离线查词、替换词库不改 API"。

建议顺序：

1. **词典包格式规范**（Manifest + `provenance.json`），先用 CC-CEDICT 的**一小部分**打通
2. FST（索引）+ SQLite（释义）双存储，验证 mmap 只读路径的实际 RSS
3. `DictionaryProvider` 的真实实现，跑通 `02` §10 的 D-01 测试（1 万词条查询 p50/p95）
4. 规则引擎最小版本：NFC 规范化 + URL/占位符保护（P0 已有雏形，需可配置化）
5. 语言识别接 fastText `lid.176.ftz`（917 KB，CC BY-SA 3.0）

**替换演练**：P1 完成后应能证明「换一套词库，`translator-api` 与 CLI 代码一行不改」。
这是设计文档 §5.4 的核心验收点。
