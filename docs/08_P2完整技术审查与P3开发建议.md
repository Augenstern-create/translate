## 0. 审查范围、事实分级与最终结论

**本轮仅获取了设计和实施报告，没有 `translator-sdk/` 的完整源代码、Git diff 或实际可运行的工程。** 以下“已实现”“通过”“实测”均指 **06 / 07 报告所陈述和展示的证据**，不是本轮重新编译或独立运行的结论。针对竞态、崩溃一致性、错误语义的判断属于**待源码核查的风险推断**，不应当被写成已发现的确定性 Bug。

**总体决定：P2 可以作为阶段性交付接受，但不能按“资源管理与移动端低内存已完整解决”对外宣称；在 P3 真实 NMT 接入前，安排一轮 P2 稳定化（P2-S）修补关键同步和语义风险。** P3 随后以单方向轻量 Marian 翻译模型 + Bergamot 参考运行时做真实 PoC，ncnn 保持可替换实验后端，不提前承诺其可运行任意 Firefox 模型。

## 1. 本轮正式拍板：四个 P3 前决策

### D-01：`glossary_id` 与术语表关系

**决定：v0.x 每次翻译默认只绑定“一份已解析的有效术语表快照”（`EffectiveGlossary`）；`glossary_id` 只用于选择，不承诺多表叠加。**

- `glossary_id: Some(id)`：资源管理器解析 id → version → 不可变快照；不存在返回明确错误，绝不静默切换默认表。
- `glossary_id: None`：可以使用宿主显式配置的默认术语表；没有配置则不处理术语。
- `ResolvedGlossary { id, version, content_digest }` 进入执行计划和缓存键。单纯使用 `id@version` 不能防止同版本内容被违规改写，因此将哈希作为更稳妥的依据。
- **多表叠加暂不对外承诺**。未来若需要，单独设计优先级（用户 > 项目 > 语言包）、同源短语冲突检测和合并哈希，不通过简单顺序拼接实现。
- 兼容策略：保留现有 builder 配置；建立请求级解析层，不直接改变已发布的字段类型。

### D-02：`AutoLocalFirst` 的词典命中是否过术语约束

**决定：`lookup()` 永不被译文术语约束改写；`translate()` 的词典直出也不直接套用 NMT 输出侧强制替换。**

- `lookup()` 返回原始多义词条、词性及出处，保证资源真实性。
- `translate()` 命中可信固定短语，可选进行**非破坏性的校验/警告**，但不擅自把词典释义替换成目标术语。
- 完整句子 NMT 译文进入术语验证；若源文明确命中绑定术语且目标译文缺失，则输出诊断，是否重译或强制改写交由显式策略控制。
- 新的术语规则需要区分**源文触发条件**与**目标译文约束**，不可只在译文中搜索某个目标语言变体就认定源文应该触发此术语（详见 §3.4）。

### D-03：SQLite v1/v2 写入与兼容

**决定：`dictionary.sqlite.v2` 是默认写入格式；v1 继续只读支持一个明确的兼容窗口，不立刻删除 v1 读取器。**

- `pack-dictionary` 默认 v2，保留 `--payload-schema dictionary.sqlite.v1` 作为兼容/重现用法，标记为 **legacy** 并在帮助文档中说明，不需要此刻删除 CLI 参数。
- v1 / v2 Payload 读取与 Manifest 协议升级继续**独立演化**，不得把 v1 字典兼容与不安全的 `pipeline_version: 1` 规则执行混为一谈。
- v2 的 `U+001F` 释义连接方式已经有“发现分隔符则拒收”的校验；可以保留，但未来如果需要支持任意字符串，应改为长度前缀/结构化字段，而非继续堆叠转义规则。
- 等真实发行版本和遥测/测试兼容矩阵明确后，再决定 v1 读取器的退役版本；不能无日期直接宣称“永远兼容”。

### D-04：真实模型内存预算与平台指标

**决定：P3 引入明确的双轨指标：`ResourceBudget` 负责预测性准入与协作式记账，`ProcessMetrics` 负责平台观测；两者不可互相冒充。**

- 继续使用 P2 的 CAS `MemoryBudget`，但将其显示名称和 API 文档写成 **accounted/estimated bytes**，不是总 RSS，也不是硬上限。
- P3 模型 Manifest 记录 `weights_bytes`、`estimated_loaded_bytes`、`estimated_peak_bytes`、测量来源设备/模型 revision；无可信估值时执行保守 fallback 或提示用户确认，不填虚构数值。
- 新增可选 `ProcessMetricsProvider`：Linux `/proc` 或 `smaps_rollup`、Windows 系统进程 API、macOS `task_info`、Android `/proc`/平台回调；平台测不到则返回 `Unavailable`，而不是 0。
- Android 在真机上量测冷加载、热翻译、连续翻译、卸载后 RSS/PSS、匿名与文件映射页、温度/耗电；不要宣称 200–250 MB 已达到。
- 不以 GPU 可用性推断性能；CPU 为基线，GPU/Metal/Vulkan 仅在同设备验证后启用。

## 2. P2.1–P2.2：协议、安装与状态仓库审查

### 2.1 已认可的设计

1. 双版本 Manifest、未知字段拒收、未知 Payload 拒绝执行，符合“明确失败优于猜测兼容”的原则。
2. 资源内容在版本目录中不可变，`staging → installed` 同盘 rename；首次安装默认激活，后续需显式激活。
3. 安装前后做校验，拒绝符号链接、路径穿越和缺失文件，具有必要的资源包边界。
4. v1 真实 CC-CEDICT 测试有端到端操作证据，但报告注明测试在文件缺失时会跳过，因此**CI 必须将固定测试资源明确标为 required**；不可用静默跳过替代发行门槛。

### 2.2 优先检查的未证实风险

| 等级 | 风险 | 为什么需要检查 | 验证/改进建议 |
|---|---|---|---|
| **P0** | `acquire_lease()` 与 `uninstall()` 的竞态 | 如果租约创建与删除检查不在同一个排他临界区，删除可发生在检查后、建租约前 | 两操作在同一资源仓库锁内完成“检查 + 标记/登记”；补双进程屏障测试 |
| **P0** | 活跃版本切换与应用持有的句柄 | 07 报告显示租约保护目录，但是否所有资源绑定路径都会持有租约需要代码核查 | `dictionary_from_store` 之外的 direct-path 入口明确为不受仓库保护；CI 覆盖活跃句柄+回滚+卸载 |
| **P0** | 锁文件的陈旧恢复 / PID 复用 | `O_EXCL` 文件锁进程崩溃后遗留；仅凭 PID 可能误认新进程；自动删锁可能误删其他进程持有的锁 | 检查锁持有者进程开始时间/启动身份；未知状态保守失败；锁恢复在互斥边界内验证 |
| **P1** | `state.json` 与目录的断电一致性 | 文件 `fsync + rename` 不总等于父目录元数据持久化；不同文件系统/Windows 语义不同 | 对已安装目录及父目录的持久化策略进行平台化验证，增加崩溃阶段注入和 `recover()` 对账 |
| **P1** | 同版本目录的不可变性 | 若仍可外部修改已安装文件，单次安装哈希不足以保证后续读取安全 | 加载前/按策略重新校验清单和内容；禁止同版本覆盖；处理外部篡改 |
| **P1** | 依赖与清理 | `cleanup` 保留“激活 + N 个历史版本”，但某版本仍被其他已安装包依赖时不能误删 | 加依赖反向引用检查；卸载/激活前检测已激活依赖关系 |
| **P1** | Linux/Windows 跨进程兼容 | 目前只给 Ubuntu 实验；Windows 上文件删除、重命名、共享方式与 Linux 不同 | Windows CI + 真机/runner 实测，而非依赖 Unix unlink 语义 |
| P2 | 精确版本依赖 | 当前只支持精确版本，不支持 semver 范围 | **保留现状**，直到真实多个依赖冲突需求出现 |

> 注意：上表不是声称源码存在这些 Bug。报告没有足够的操作交错和崩溃注入证据来排除它们，因此应按风险等级补测。

### 2.3 锁与租约的推荐事务边界

```text
acquire_lease(id, version):
  store_lock.lock()
  check installed + not deleting
  create lease atomically
  store_lock.unlock()
  return LeaseGuard

uninstall(id, version):
  store_lock.lock()
  check active/history/installed-dependent refs
  check all valid and unknown leases
  transition to Deleting (if state machine supports it)
  delete safely / defer deletion
  commit state
  store_lock.unlock()
```

上述是**语义要求**而不是可直接复制的代码：锁等待时间、I/O 长度、Windows 共享模式、崩溃恢复要结合实际实现。特别是不可将“检查租约”与“实际删除”放在未保护的两个阶段。锁文件本身应区分 **持有者身份**（进程 + 启动标识 + nonce）和 **锁元数据**，不能只凭 PID 判活。

如果不希望跨进程删除时持锁执行大量 I/O，可以在锁内将目录**原子重命名为 tombstone**（并持久化删除意图），解锁后异步清理，但必须先证明重命名与正在映射/打开的资源在各平台上可行；首版可用短事务保守执行。

## 3. P2.3–P2.4：预算、术语与诊断审查

### 3.1 内存预算目前的准确定位

报告实现的是 `MemoryBudget::try_reserve()` CAS 记账，能够避免同时预留超过**设定的账面配额**，这是一项有价值的并发正确性保证。它**不能**证明模型推理时实际 RSS 不超限。

此外，07 §2.1 的 SQLite 页缓存大小是**配置值**，不应在文档中称为“精确 RSS”；SQLite 可能调整缓存、分配额外内存，mmap/页表/动态库也无法简单归属。建议把“精确”改成“配置上界或目标值（需以 sqlite3 实测核对）”，继续保留估算表中的不确定性标记。

**P3 最小接口建议**：

```rust
pub trait ProcessMetricsProvider: Send + Sync {
    fn snapshot(&self) -> Result<ProcessMemorySnapshot, MetricsError>;
}

pub struct ProcessMemorySnapshot {
    pub rss_bytes: Option<u64>,
    pub peak_rss_bytes: Option<u64>,
    pub anonymous_rss_bytes: Option<u64>,
    pub file_rss_bytes: Option<u64>,
    pub gpu_bytes: Option<u64>,
}
```

此接口应放在平台适配 crate，由 `translator-core` 只消费抽象；真实平台的字段可能不可获取，应接受 `None`。预算不承诺对动态 C++ 分配器或 GPU 驱动施加物理硬限制。

### 3.2 single-flight / TTL / LRU 推迟：有条件同意

07 报告的理由成立：**P2 尚未具备真实按需加载的 NMT 生命周期**，此时写空壳只是增加复杂度。因此不需要为了勾选 P2.3 清单而补假的 single-flight、TTL/LRU。

**但这些能力在 P3 首个真实模型接入时转为 P1 必做**：

- 同一 `model-id@revision + runtime` 的并发请求只触发一次实际加载。
- 加载失败后所有等待者得到同一个明确错误，允许有界重试，不形成连续重载风暴。
- 活跃推理持有租约或模型 guard，卸载必须等待其完成。
- 冷模型按需加载；空闲时可 TTL 卸载；因内存压力可主动清理；默认不同时保留多个大型模型。
- 取消和超时只撤销等待与后续任务，不在 C++ 正在执行推理时强制析构资源。

### 3.3 请求级结构化诊断：接受，但要审计缓存语义

`translate()` / `translate_with_diagnostics()` 复用同一 `Coordinator::run`，以及缓存同时保留 `result + diagnostics`，是正确的方向。仍需代码审查以下情况：

1. **`cache_hit` 应是每次调用的观测状态**：从缓存取出旧诊断时，应标记当前请求 `cache_hit=true`，不能把首次请求 `false` 原样复制。
2. 某些与本次调用有关的字段（运行时耗时、回退链、当前资源状态）不应全部依赖旧缓存快照；建议区分 `TranslationProvenance`（可缓存）和 `RequestDiagnostics`（实时生成）。
3. 诊断虽然只含片段，但 URL、模板变量和术语内容可能包含敏感数据；**不得默认输出到集中式日志或崩溃上报**。
4. 术语表版本、模型 revision、规则版本、解码参数、语言方向及网络权限域发生变化时必须正确失效缓存。

### 3.4 输出术语“强制替换”存在产品语义风险（P0）

07 报告的示例：把 mock 译文里的 `planet earth` 自动改为 `world`，同时以 `TermMismatch` 警告记录。这验证了**文本替换功能**，但没有证明“译文在源语言语境下应当使用该目标术语”。

传统术语约束需要至少区分：

- `source_pattern`：源文中何时认定术语被触发；
- `preferred_target`：目标语期望译文；
- `target_variants`：可接受/不推荐的目标词变体；
- `context` / `case_policy` / `inflection_policy`：用于控制歧义或形态变化；
- `mode`：仅验证、警告、重新解码或经用户显式同意的有限文本替换。

**拍板：默认策略调整为 `Warn`（或在没有术语表时 Off）；`Enforce` 只能在显式启用并满足确定性安全条件时改写译文。** 当前将 `Enforce` 设为默认，且只对目标文本变体做替换，容易把原本正确的句子改错。若已有调用者依赖默认 Enforce，要在版本说明中标记默认行为变更；在未公开发行前宜立即修正。这里不建议为了实现“约束”而无条件改写未知语境文本。

优先将 P3 的目标定为 **“源触发条件 + 目标译文缺失检测 + 诊断”**，真正的 constrained decoding 需要视 Marian/Bergamot 实际能力另起 PoC。

### 3.5 规则保护跨度：保持单扫描器，增加边界测试

06 已将 `protected_spans()`、`split_protected()`、`protect()` 对齐，金样本与实际 `RuleEngine::run()` 复用一套受保护跨度语义，这是重要修复。P3 接真实 Tokenizer 后补：

- 混合 Unicode、emoji、组合字符的 UTF-8 字节偏移；
- URL 包含标点、代码中含反引号、嵌套花括号、未闭合代码片段；
- 多次规范化后源/输出偏移变化；
- Tokenizer 改写占位符导致恢复失败时严格失败或明确警告；
- 保护区间不重叠、不越界，且每次分段后仍可正确恢复。

跨段 marker / NMT 直接理解跨度的契约继续**推迟到 P3 实际模型基准**，不为理论方案提前绑定引擎接口。

## 4. P2.5：SQLite v2 审查与接纳标准

07 提供的同机对照有明确指令、样本规模、p50/p95/p99 和历史 v1 回归；**同意将 v2 作为新包默认写入格式**。同时要求：

1. v1 读取必须持续有契约测试，不允许为了 v2 删除历史数据兼容性。
2. 释义按 U+001F 分隔：文档写清限制、打包拒收和边界测试，避免把“不支持控制符”当成语料损坏。
3. 进一步测 `lookup(limit > 1)`、前缀查询、多义词、简繁共键、长释义、多线程读竞争，不只测单词精确查询。
4. 若将来支持外部导入自由文本释义，优先设计长度前缀或 MessagePack 等显式字段编码，避免在分隔符体系上无限叠补丁。
5. 对完整进程 RSS 的测量要与查询延迟同时报告；数据库文件缩小不等于 RSS 按比例下降。

## 5. P3 开发方案：分两段执行，先稳定化再接真实模型

### P2-S（P3 准入前稳定化，建议先完成）

| 任务 | 交付 | 优先级 | 验收 |
|---|---|---|---|
| S-01 租约/卸载原子性 | 共享跨进程临界区或等价状态机 | P0 | 双进程/屏障交错测试，活跃租约永不误删 |
| S-02 锁文件回收审计 | PID 复用/进程启动标识/损坏锁处理说明 | P0 | 崩溃、死 PID、未知 PID 和并发恢复测试 |
| S-03 术语安全默认值 | `Warn` 默认；源触发/目标校验的最小表示 | P0 | 歧义词/保护跨度/上下文样本，无非预期改写 |
| S-04 缓存诊断回归 | 缓存命中当前态、资源版本失效 | P1 | 两次相同翻译诊断可信，升级资源不复用旧译文 |
| S-05 安装状态恢复 | staging/state/installed 三方对账 | P1 | 注入各写入点失败/重启后恢复，旧版本可用 |
| S-06 文档与 API 一致性 | ADR、Feature、兼容矩阵、known limits | P1 | `01/05/06/07` 无冲突，差异有 ADR |
| S-07 平台预备 | Windows 构建与 macOS CI；Android NDK 安排 | P1 | 代码能在目标平台编译；真机性能仍待测 |

> **禁止新增“虚假完成”状态**：S 阶段只对真实测试范围签字。测试环境若暂时无法覆盖 Windows/macOS/Android，明确记为 pending。

### P3.1：首个真实本地 NMT（单语言方向 PoC）

**目标**：保持 `Translator::translate()`、`TranslationEngine` 和 `InferenceBackend` 不变，接入一个真实轻量 Marian 翻译模型，拿到正确译文与可测的内存指标。

1. **锁定可复现资源**：优先核查 Mozilla 当前 Firefox 模型注册表中单个方向的 tiny / base-memory Marian 包；若目标方向不存在，选合法可分发的 OPUS-MT 替代。记录模型 revision、Tokenizer、格式、许可、下载/转换校验和。
2. **先跑参考实现**：独立 Bergamot/Marian CLI 验证语言方向、Tokenizer、生成参数、译文；收集 20/100/500 字样本与术语、数字、URL 的金样本。
3. **建 `runtime-bergamot` 适配器**：只让 FFI crate 触碰原生句柄；用 worker/actor 包裹不可安全共享的对象；明确线程、生命周期与崩溃边界。
4. **接入资源管理**：Manifest `ModelCompatibility`、模型租约、首次加载/重复加载 single-flight、超时/取消、卸载；不存在的模型返回 `ResourceNotInstalled` 和资源建议。
5. **接入执行计划**：完成 `ResolvedExecutionPlan`（engine/runtime/model revision/tokenizer/规则与术语指纹/解码参数/语言方向/隐私域），以稳定哈希构造缓存键。禁止仅以 `id@version` 或 `None model_id` 缓存真实 NMT。
6. **端到端验证**：对照参考实现译文质量/差异，验证两次请求复用模型、主动卸载、模型热切换期间旧请求完成、默认无网络。

**P3.1 完成门槛**：

- [ ] 真实模型完成至少一个语言方向的整句翻译，不是 Mock 标记输出。
- [ ] 同一模型 revision + 同一解码参数下，参考框架与 Rust SDK 行为一致或差异可解释。
- [ ] 模型启动/翻译/卸载形成可重复、无显著泄漏的生命周期测试。
- [ ] 同时请求单一模型不会重复加载；活跃推理中禁止卸载。
- [ ] 空闲资源释放后可重新加载；错误与恢复行为明确。
- [ ] 不修改 UI 相关代码，公共 API 不暴露 C++ 原生对象。
- [ ] 默认远程权限仍关闭；没有上传原文的意外路径。

### P3.2：跨平台内存与 ncnn 可行性对照

- Ubuntu x86_64：建立 CPU 冷启动、热模型 p50/p95、峰值 RSS、连续 10 分钟测试。
- Windows x64：至少构建与功能烟测，补打开文件/删除/回滚及 FFI 链接行为。
- macOS arm64：CI 构建与集成测试；若无硬件，性能明确记 pending。
- Android arm64：必须用真机测试 NDK/JNI、应用退后台、内存压力、进程 PSS、热降频及运行时包体；没有真机则不能声称移动端流畅。
- ncnn PoC：仅在完成 Encoder/Decoder、Cross-Attention、动态形状、Tokenizer、EOS、量化数值一致性后进入同模型对照；“pnnx 导出成功”不是验收通过。
- 按可用性/质量/内存/延迟评分选择默认后端，不因 Rust 原生、WGPU 或 ncnn 名称直接判优。

### 5.3 P3 模型加载最小状态与调度接口（示意）

```rust
pub enum ModelState {
    Unloaded,
    Loading,
    Ready,
    Evicting,
    Failed,
}

pub struct ModelKey {
    pub model_id: String,
    pub revision: String,
    pub runtime_id: String,
}

pub trait ModelRuntimeManager: Send + Sync {
    fn acquire<'a>(&'a self, key: &'a ModelKey)
        -> BoxFuture<'a, Result<ModelGuard, TranslationError>>;
    fn metrics(&self) -> RuntimeMetricsSnapshot;
}
```

以上只是接口意向，不是已编译代码。真正的 `ModelGuard` 必须明确 worker 归属、取消/析构顺序；`ModelKey` 还应在需要时包含精度/后端设备配置。同样 `BoxFuture` 需从公共插件契约模块复用，不应在核心层引入某个 NMT runtime 的类型。

## 6. 补充测试矩阵与故障注入清单

| 编号 | 情景 | 期待行为 | 最迟阶段 |
|---|---|---|---|
| C-01 | 进程 A 申请租约，进程 B 同时卸载 | 只有一个动作成功进入合法状态；不能出现“租约成功但资源已删除” | P2-S |
| C-02 | A 活跃租约，B 执行 cleanup/rollback/activate | 活跃句柄仍可读；被租用目录不被删除 | P2-S |
| C-03 | 安装复制完成、写 state 前杀进程 | recover 后现有激活包不损坏，孤儿可识别/回收 | P2-S |
| C-04 | 两进程抢锁、死锁文件和 PID 复用 | 不越权清理活锁；锁超时有诊断信息 | P2-S |
| C-05 | manifest 与 SQLite `user_version` 不一致 | 拒绝打开，绝不返回空释义 | 已有，持续回归 |
| C-06 | 完整句子包含 URL/代码/占位符及同名术语 | 受保护段零误改；校验仅作用于真正触发的术语 | P2-S |
| C-07 | 相同请求第二次命中缓存 | 本次 `cache_hit` 正确，译文与稳定诊断一致 | P2-S |
| C-08 | 同模型同时 10 个翻译请求 | 只加载一次、推理串行/限流行为可解释 | P3.1 |
| C-09 | 加载/翻译过程中取消与 timeout | 不悬挂、不提前释放 native 句柄 | P3.1 |
| C-10 | 内存预算不足、模型估计缺失 | 明确拒绝或可解释降级，无 OOM 假承诺 | P3.1 |
| C-11 | Win/macOS/Android 真实资源路径与长文件名 | 不依赖 Unix 特性；平台错误可诊断 | P3.2 |
| C-12 | FFI `panic` / 异常、失效模型包 | 不穿越 C ABI；资源与错误可回收 | P3.1 |

建议 `cargo test --workspace --all-features`、Clippy、fmt 继续保留，并增加**跨进程独立二进制测试**（单进程 `std::thread` 无法证明 lockfile 和文件租约正确）。真实 NMT 的基准报告包含：机型、系统、模型 revision、量化方式、CPU/线程数、句长、Beam、预热条件、RSS/PSS 与 p50/p95。

## 7. 公开 API 与插件化边界：必须保持的原则

1. `translator-api` 不依赖具体 `Bergamot` / `ncnn` / SQLite 句柄；由 composition root 注入实现。
2. 引擎 Trait、字典 Provider Trait、InferenceBackend Trait 的版本兼容与能力发现保持分离。
3. 资源包 Manifest 与内层模型/词典 Payload 独立版本化；禁止猜格式，禁止随意绕过完整性校验。
4. 原生 FFI 的 `Send + Sync` 必须通过 worker/actor 实现线程安全语义，不可对未经验证的指针做 `unsafe impl`。
5. 输入/输出隐私域与网络许可写进执行计划；远程默认关闭，不以 NMT 失败为由自动上传文本。
6. `translate_with_diagnostics()` 与 `translate()` 共享执行路径；`explain_rules()` 继续定位为预览入口。
7. 底层 Runtime 的替换必须通过同一套契约、译文回归、内存和延迟测试；不可只替换文件扩展名。

### 9.1 推荐执行顺序（批准的范围）

```text
P2-S：租约/锁/术语安全/缓存与恢复的稳定化
  ↓ （通过阻断级验收）
P3.1：单方向 Marian + Bergamot 真实推理与资源生命周期
  ↓ （真实译文、加载/卸载、内存报告均通过）

  ↓
```

**最终拍板**：不回滚 P2 的架构成果，不为 8–9 µs 的词典查询继续过度优化；集中资源修补跨进程安全和术语语义，然后用真实轻量 NMT 驱动接下来所有资源管理与性能决策。这是最稳妥地实现低内存、跨平台、可替换翻译 SDK 的路径。
