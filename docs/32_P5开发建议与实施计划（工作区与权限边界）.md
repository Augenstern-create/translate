## 0. 决策摘要

本阶段采用 **Windows 实体机验证优先、Android 保持已证明的工具链基线、Linux 现有功能不回退** 的策略。项目源码、测试输出、下载物、构建缓存、临时文件和生成的报告，默认均限制在用户指定的**唯一可写工作区**：

```text
E:\augenstern\translate
```

**四条不可覆盖的硬性约束：**

1. **工作区外只读允许，任何修改必须事先获用户明确批准。** 包括创建、覆盖、删除文件和目录，以及对 Git 全局配置、注册表、PATH、Defender、安全策略、服务、环境持久配置、已有工具安装位置等的更改。该约束**与是否需要管理员权限无关**。
2. **任何管理员权限操作必须逐项先申请用户批准。** 即使操作目标位于项目文件夹，提权本身也不是默认获授权动作；不得因为 SSH 会话已有管理员令牌就直接执行系统修改。
3. **Python 固定使用 `D:\Anaconda3` 内的解释器**，不以 PATH 中的裸 `python`、`py` 或 `D:\python\python.exe` 为默认值。解释器与 conda 环境的读取和运行可以进行；涉及 Anaconda 安装目录、base 环境、包缓存等目录的任何写入需另行批准。
4. **Rust 已由用户更新，不应再自行安装或切换工具链。** 首先只读确认 `rustc -vV`、`cargo -V`、`rustup show`；需要变更时再申请授权。代理允许在**当前进程/当前命令**中临时设置，不改系统代理、用户环境变量或 Git 全局代理配置。

**权限优先级：** 本文最新工作区与授权约束优先于旧文档中 `D:\dev\translate-workspace`、`C:\dev`、全局 `core.autocrlf`、Defender 排除等建议。所有旧脚本必须先审计输出路径，再执行。

## 2. 文件与操作权限矩阵（执行前强制检查）

| 操作 | 位于 `E:\augenstern\translate` 内 | 工作区外 | 是否需额外审批 |
|---|---|---|---|
| 查看、读取、校验哈希 | 允许 | **允许只读** | 否（需遵循已有访问权限） |
| 创建/修改项目源码、`docs`、测试数据、构建产物 | 允许 | **禁止直接执行** | 目录外须先获批 |
| 删除项目产生的可重建缓存 | 限已确认属于本项目的路径，删除前校验 | 禁止直接执行 | 目录外须先获批；不做泛化递归删除 |
| `cargo build/test/clippy/fmt` | 可执行，但先确保缓存、临时路径均在工作区 | 不得写用户目录/工具链目录 | 若不能将写入限制在工作区，先获批 |
| `pip install` / `conda install` / `rustup update` | 不作为默认开发动作 | 可能修改 Anaconda、Rust、缓存/环境 | **必须获批**，包括无管理员权限的安装 |
| 当前 PowerShell 进程设置代理环境变量 | 允许 | 不产生持久修改 | 不需要；不得使用永久 `setx` |
| `git config --local` / 项目 `.gitattributes` | 允许 | 不适用 | 不需要（项目内） |
| `git config --global/--system` | 不适用 | 修改外部配置 | **必须获批** |
| Defender 排除、PATH、注册表、服务、系统安装 | 不以目录判断 | 系统级修改 | **必须先获批，涉及管理员权限也须明确获批** |
| SSH 只读勘察 | 无落地写入时允许 | 可读取现有工具与配置 | 无修改则无需；如脚本下载/保存到工作区外须先获批 |

> **执行准则：** 既有权限足够，不等于允许修改。脚本或第三方工具若可能隐式写入 `%TEMP%`、`%USERPROFILE%`、`%LOCALAPPDATA%`、`%APPDATA%`、`%USERPROFILE%\.cargo`、`%USERPROFILE%\.rustup`、Conda base 或其他磁盘位置，必须先重定向至项目工作区；无法保证时停止执行并申请批准。仅读取外部目录不受此限制。

## 3. Windows 工作区布局与隔离策略

建议在唯一可写根目录内建立：

```text
E:\augenstern\translate\
├── translator-sdk\                 # 项目源代码/已有 Git 仓库（如原本就在此，不另复制）
│   ├── crates\
│   ├── apps\
│   ├── tools\
│   ├── fixtures\
│   └── docs\
├── .build\
│   ├── target\                     # CARGO_TARGET_DIR
│   ├── cargo-home\                 # 仅工作区项目依赖与构建缓存
│   ├── temp\                       # TEMP/TMP/TMPDIR
│   ├── python-cache\               # PIP_CACHE_DIR/PYTHONPYCACHEPREFIX
│   ├── model-cache\                # HF_HOME / 模型下载中间文件
│   ├── ort-dist\                   # 经许可审查的 ORT 部署包
│   └── reports\                    # 验证原文、指标 JSON
└── .staging\                       # 需要时才建立的临时传输/打包目录
```

目录可按现存项目形态调整，**不得因为本文示例而覆盖/移动现有文件**。若 `E:\augenstern\translate` 本身就是 Cargo Workspace 根目录，则在该目录直接创建 `.build`，无需再嵌套 `translator-sdk`。

### 3.1 建议的当前进程环境示例（PowerShell）

```powershell
$ProjectRoot = 'E:\augenstern\translate'
$WorkRoot = Join-Path $ProjectRoot '.build'
$env:CARGO_TARGET_DIR = Join-Path $WorkRoot 'target'
$env:CARGO_HOME = Join-Path $WorkRoot 'cargo-home'
$env:TEMP = Join-Path $WorkRoot 'temp'
$env:TMP = $env:TEMP
$env:TMPDIR = $env:TEMP
$env:PIP_CACHE_DIR = Join-Path $WorkRoot 'python-cache'
$env:PYTHONPYCACHEPREFIX = Join-Path $WorkRoot 'python-cache\pyc'
$env:HF_HOME = Join-Path $WorkRoot 'model-cache'
$env:PYTHONNOUSERSITE = '1'
$Python = 'D:\Anaconda3\python.exe'

# 仅在确定目录不存在时在工作区内创建；不写入项目外。
New-Item -ItemType Directory -Force -Path $WorkRoot,$env:CARGO_TARGET_DIR,$env:CARGO_HOME,$env:TEMP,$env:PIP_CACHE_DIR,$env:PYTHONPYCACHEPREFIX,$env:HF_HOME | Out-Null
& $Python --version
rustc -vV
cargo --version
```

**注意：** 仅设置项目内 `CARGO_HOME` 可能使 Cargo 找不到原本安装在用户目录的 `rustup` 代理/配置，或触发依赖重新下载。必须先用**只读探针**核实 `where.exe cargo`、`where.exe rustc`、`RUSTUP_HOME`、工具链所在位置；必要时将 `RUSTUP_HOME` 显式指向**现有**工具链目录并确保只读使用。不应为了让命令通过而重装 Rust 或改动外部目录。`cargo`/`rustup` 某些子命令可能有写入行为，需要先在本项目范围内做最小验证。若无法证明外部零写入，先申请授权。

**Python：** 使用 `& 'D:\Anaconda3\python.exe' script.py`，不要先 `conda activate base` 再依赖 PATH。默认仅运行已有依赖的脚本；缺包时先列出具体依赖和安装目标，获批后再进行环境变更。

**代理：** 只有在下载确实需要时，在当前进程临时设置 `$env:HTTP_PROXY`、`$env:HTTPS_PROXY`、`$env:ALL_PROXY`（地址以当前实际可用代理为准）；不修改持久环境变量、全局 Git 配置或系统网络设置。下载产物写入工作区。

### 3.2 Git 与换行策略

- **不执行**旧报告建议的 `git config --global core.autocrlf false`、`core.longpaths true`，因为它们写到工作区外。
- 可以在项目仓库内用 `git config --local core.autocrlf false`、`core.longpaths true`；先检查是否存在项目 `.gitattributes`，必要时在项目内维护行尾策略并单独验证模型锁文件、JSONL 与 fixtures 的哈希。
- 禁止未经确认的 `git reset --hard`、`git clean -fdx`、大范围覆盖或删除。
- 若项目文件不在指定工作区，先只读确认源位置和传输方式；向工作区内导入时先验证目标不会覆盖现有文件。

## 4. P5 工程目标与非目标

### 4.1 当前必须完成

1. Windows 现有工具链在**指定工作区**构建并验证稳定 Rust Core、CLI、字典、规则、资源仓库和插件门禁。
2. 记录 `rustc/cargo` 实际版本、MSVC/Windows SDK 版本、构建与测试命令、退出码、原始日志。
3. 验证 Windows 路径（空格、中文路径）、UTF-8/ACP936、换行与 FST/SQLite、资源安装/卸载行为。
4. ORT 作为 Windows NMT 可选后端：先做 CPU 功能可行性与运行时版本隔离；如本阶段需真正翻译，再在项目内准备明确校验的模型文件。
5. 保证 Linux 已通过的默认路径没有被 Windows 专用修补破坏，平台特定逻辑留在 adapter 或 `cfg` 分支。
6. 输出可复现的 Windows 验证报告，并把未实测能力标为 pending。

### 4.2 当前明确不做

- 不擅自安装/切换 Rust、Conda/Python、VS、Windows SDK、NDK。
- 不修改系统 PATH、Defender 排除、注册表、服务、系统代理或 Git 全局配置。
- 不新建 `D:\dev`、`C:\dev` 或将仓库复制到工作区外。
- 不把 Windows 的 Bergamot 适配列为完成项；其平台门禁报 `CapabilityUnavailable` 是当前预期行为。
- 不把 x86_64 AVD 冒烟测试说成 Android ARM64 真机验收。
- 不为跨平台“看起来完整”而加入空实现或无证据的性能承诺。

## 5. 分阶段实施（每阶段独立验收）

### P5.1 — 工作区与环境只读核验

**任务：** 只读扫描既有目录、源码版本、Rust/MSVC、Anaconda Python、ORT、代理可达性、磁盘空间。形成 `fixtures/p5/windows-env-current.json`（写入工作区）。明确 Cargo、Rustup、Python 与 native 工具可能的隐式写入位置。

**验收：** 不发生工作区外修改；报告有路径与版本证据；发现工作区外必要写入时列为待批准事项。

### P5.2 — 构建与回归（W1–W5、W7–W10）

**任务：** 完成项目内构建输出隔离；跑 `cargo fmt --check`、Clippy、默认与 all-features 测试、真实字典、资源仓库、规则和 CLI；覆盖中文/空格路径；执行 Bergamot 平台门禁测试；Python 脚本使用 Anaconda 绝对路径。

**验收：** 记录命令、实际退出码、测试统计和日志；失败区分代码、Rust 版本、依赖下载、ABI、字符编码、文件系统差异；不把 Linux 结果当成 Windows 结果。

**建议命令（仅在确认无工作区外写入风险后执行）：**

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy --workspace --all-features --all-targets -- -D warnings
cargo test --workspace
cargo test --workspace --all-features
& 'D:\Anaconda3\python.exe' tools\p5\windows-preflight.py fixtures\p5\win-recon-nan-windows.json
```

最后一条路径以仓库真实布局为准；不要假定文件必在此处。旧报告对 `cargo fmt` 的工具链差异采取注记，但**不自动忽略真实格式失败**，应核查 `rustfmt` 的具体差异。

### P5.3 — Windows ORT 后端试运行（W6）

**先做版本决定，再下载或链接：**

- **优先方案：** 与 Rust `ort` crate 所需 ABI/API 匹配的 Windows 原生运行库，显式选择 CPU Execution Provider（即使预编译包带 DirectML，也不应默认视为测了 DirectML 性能）。记录实际 DLL 文件路径、版本、哈希与加载顺序。
- `D:\Programs\onnx` 中旧的 ORT 1.29 CUDA DLL **只允许只读检查**，不得覆盖、重命名或移除。需要避免 DLL 串扰时，应在**当前子进程**构造受控 DLL 搜索路径/环境，而不改全局 PATH。
- 若下载需代理：只对该次进程设置代理；所有缓存/下载与模型写入 `E:\augenstern\translate` 内。
- 如所需版本不可得或必须更改外部环境，明确阻塞并申请授权，不自动退到不兼容运行库。

**验收：** 构建完成、模型与 Tokenizer 哈希一致、真实输出符合金样本基本约束、独立记录冷加载/热翻译/峰值 RSS、可解释的 `CapabilityUnavailable` 和模型缺失错误。

### P5.4 — Windows 资源管理与故障测试

**优先测试：** 版本化目录、安装/校验/激活/回滚、文件正在 mmap/SQLite 打开时的租约保护、跨进程锁、安装中断后的 audit/recover、依赖反向引用、缓存修订隔离、路径遍历/符号链接/大小写路径差异。

**验收：** 无误删活跃资源、不产生未说明的目录外写入；故障注入仅针对项目内**专用测试仓库**；不得对真实用户目录、现有非测试资源做破坏性测试。

### P5.5 — Android 保留现有证据，待真机补验

- 现有 Linux 机上的 NDK r30 + x86_64 AVD JNI 测试属于**既有验证结果**；Windows 新工作区无需重复下载安装 NDK。
- Windows 上仅允许更新与平台无关的 API 契约、Manifest、JNI 预留接口和测试文档；不把 JNI 冒烟直接升级为真正翻译 SDK 的 Android 交付。
- ARM64 实机功能、内存、温度与功耗测试继续 `pending`，待设备可用后独立开展；届时仍需遵守工作区外写入审批要求。

交付 `docs/32_P5_Windows实际验证报告.md` 或**下一个未占用编号**（先只读核对现有 docs，避免覆盖），并同步 README、CHANGELOG、平台能力表。报告包含已执行/未执行事项、日志、版本、明确异常、待批系统操作。当前不发布“全平台已支持”。

## 6. 重点风险与缓解

| 风险 | 后果 | 对策 |
|---|---|---|
| 旧报告默认 `D:\dev` / 系统配置写入 | 违反用户边界 | 全部替换为 `E:\augenstern\translate`；配置改为项目内或本进程临时值 |
| Cargo/Rustup/Python/Conda 隐式外部写入 | 无意修改其他目录 | 环境与缓存隔离、只读预检；不能确定时先停下询批 |
| Rust 版本已更新、报告仍是 1.97 | 基线误判 | 以本机新只读实测为准，不擅自升级 |
| MSYS2 版 Python/编译器在 PATH 前 | ABI/编码混乱 | 固定 `D:\Anaconda3\python.exe`；MSVC 构建环境明确化、不改 PATH 持久值 |
| ORT Windows DLL 与 API 版本不符 | 崩溃/未定义行为 | 用受控子进程及明确版本的项目内 DLL；记录实际加载 DLL |
| `core.autocrlf=true` | 模型锁与 fixtures 哈希漂移 | 项目内 `.gitattributes` / local Git 配置，无全局修改 |
| Windows 文件使用中删除语义不同 | 资源仓库清理失败 | 租约先行、故障注入测试、保守拒删 |
| Defender 扫描影响构建耗时 | 性能基准偏慢 | 先接受耗时并记录；**不自动设置排除项** |
| Android 无 ARM64 设备 | 无法验证移动端兼容 | 保持 pending，不以 AVD 代替真机 |

## 7. 需提前单独申请批准的操作（不是默认待执行指令）

1. 修改 `E:\augenstern\translate` 以外的任何文件/目录，包括 `D:\Anaconda3`、`D:\Programs\onnx`、`C:\Users\...\.cargo`、系统/用户临时目录、用户级 Git 设置。
2. 安装/更新 Rust 工具链、VS、ORT、Python/Conda 包或系统组件（包括普通权限安装）。
3. 修改 Defender 排除项、防火墙、注册表、系统 PATH、服务、代理持久化配置或其他需要管理员权限的操作。
