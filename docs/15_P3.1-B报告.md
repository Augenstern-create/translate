## 0. 结论与边界

**"Linux Rust host → 进程外 worker → Bergamot → 真译文"这条闭环已经跑通**：`Hello world!` → `你好,世界!`，且宿主在真实 native `abort()`（SIGABRT）与外部 `SIGKILL` 下都存活。

本轮**没有**、也不声称做到：占位符保护（P3.1-C）、single-flight/租约/执行计划/缓存（P3.1-D）、SDK 门面与 CLI 端到端接线（P3.1-E）、任何非 Linux 平台、权重再分发许可（P3.4）。

真实模型依旧**不入库**：仓库里只有锁定记录、金样本、配置模板与本轮的基线 JSON。

## 1. 实际实现内容

### 1.1 架构：三层进程

```text
宿主进程（cargo test / 未来的 translator-api）
   │  长度前缀帧（4B BE + JSON，8 MiB 上限）+ request_id/epoch/revision
   ▼
nmt-worker（Rust，监督者；~2.7 MiB RSS）
   │  行模式 JSON（worker 私有，不向上暴露）
   ▼
bergamot CLI（native，真实 Marian；稳态 ~342 MiB / 峰值 413.8 MiB）
```

`docs/14` §3.2 推荐的是 "worker 内链接 C ABI bridge"；§3.3 同时给出**替代方案**：若 Bergamot 无法稳定通过 C ABI 单句调用，可以把参考 CLI 的长驻服务放进 worker 内部。本轮采用替代方案，理由与代价见 §3 D-10。

关键不变式：**native 死 = 模型没了 = worker 立刻以退出码 70 退出**。这样 P3.1-A 已有的语义（`WorkerExited` → 下一次请求才重启、不静默重放、`loaded` 作废）不需要任何改动就继续成立。

### 1.3 模型隔离快照（B-P0-02）

`docs/14` §3.5 拍板"隔离快照优先于路径二次校验"。实现顺序：

1. **便宜的预检查**（存在/非符号链接/普通文件/大小）——坏输入在这里就失败，不浪费复制；
2. **复制与摘要用同一次读**：从源文件读到缓冲区，一边写副本一边喂 `Sha256`，比较的是**副本的字节**；
3. 副本落在 `snap-<pid>-<seq>-<digest8>/`（目录 0o700、文件 0o400）；
4. 之后 worker 收到的路径**只在副本里**，宿主不再碰源目录；
5. worker 在 spawn native **之前**用 `ModelSpec::verify_digests()` 再核一遍（打开前、由将要打开它的人确认）；
6. 快照活到 `unload`/`shutdown`/传输层 Drop；被 SIGKILL 的残留由 `prune_stale_snapshots()` 按目录名里的 pid 清理。

**为什么不是"先全量校验、再复制"**：那样中间有窗口，而且要把 49.5 MiB 读两遍。
"复制出来的字节就是被校验的字节"这个顺序更强，实测也把 `model_preparation_ms` 从 **766 ms 降到 262 ms**（§2.4）。

诚实边界：0o400/0o700 只挡"手滑"和跨用户读取，**挡不住同用户的恶意进程**；没有用 `openat`/目录 FD/seccomp。这一条写进代码注释与 §3 D-13。

### 1.4 类型化配置生成（B-P0-05）

`config.rs` 只接受 `BergamotOptions`（cpu_threads / beam_size / max_input_chars / source_language / target_language 五个有范围检查的字段），其余一律由快照路径与固定常量生成：

- `models` 段**只有一项**；`shortlist` 是独立键（P3.0 实测把 lex 写进 `models` 会让 Marian 直接 `abort()`）；
- `mini-batch`/`maxi-batch` 固定为 1、`workspace: 128`、`normalize: 1.0`；
- 路径必须是**绝对路径**、不含控制字符，双引号与反斜杠转义；
- 语言标签只允许 ASCII 字母数字与 `-`/`_`。

调用方**无法**把任意 YAML/CLI 片段传给 native。

### 1.5 分阶段超时（B-P0-04）

| 阶段 | 初值 | 超时后 |
|---|---:|---|
| `Load` | 30 s | 杀 worker，`loaded` 作废，错误 `Timeout{operation:"load"}` |
| `Translate` | 15 s | 杀 worker，错误 `Timeout{operation:"translate"}` |
| `Health`/`Unload`/`Shutdown` | 10 s | 同上 |
| 终止升级 | shutdown 帧 500 ms → SIGTERM 500 ms → SIGKILL | 每级都有上限 |

排队截止时间**未实现**（没有队列，并发恒为 1）：`docs/14` §1.1-2 提到的"锁等待不受超时约束"因此仍然成立，如实记录在 §3 D-14。

### 1.6 原生进程的两条硬要求

1. **stdio 不污染**：native 的 stdout 由 worker 的行读取线程独占解析，native 的 stderr 逐行转发到 worker 的 stderr（再加宿主侧 64 行环形缓冲）；worker 自己的 stdout 只写帧。
2. **不产生孤儿**：native 用 `PR_SET_PDEATHSIG(SIGKILL)` 启动——宿主在加载期超时会直接 SIGKILL 整个 worker，此时 native（400+ MiB）必须跟着死。`bt10` 用"扫 `/proc/*/cmdline` 找 `nmt-worker-` 残留"来验证这一条。

### 1.7 卸载语义

`Unload` = 结束 native 进程 + 删快照 + 删临时配置；**worker 进程保留**（2.7 MiB）。
Bergamot 没有可靠的"卸载模型但保留进程"的 API，所以这是 `docs/14` §7 明确允许的"以结束并重建 native 作为卸载"，冷启动代价在 §2.4 有实测。

### 1.8 测试与工具

- 真实模型验收 12 条（`tests/real_bergamot.rs`，默认 `#[ignore]`，需要 `NMT_BERGAMOT_BIN` / `NMT_MODEL_DIR`）；
- mock 回归 17 条（`tests/worker_process.rs`）原样保留，零改动；
- 新增单测 11 条（配置生成 6 + 快照 5）+ worker 行协议清洗 1 条；
- `examples/p3_1b_evidence.rs`：一条命令产出 §2.4 的全部数字，并可写基线 JSON。

### 2.3 真实崩溃路径的证据（B-P0-01）

两条互相独立的崩溃路径，都在 Rust 测试进程里被抓到：

1. **加载期 native `abort()`**（缺权重文件，P3.0 记录的原始失败场景）：
   ```
   native 崩溃后宿主收到：运行时初始化失败：native 在加载完成前退出（没有 load 回执）
   ```
   native 侧真实日志（worker stderr 转发，宿主环形缓冲保留）：
   ```
   Error: Model file does not exist: …/model.does-not-exist.bin
   Error: Aborted from void marian::ConfigValidator::validateOptionsTranslation() const
   ```
   对外错误码 `RuntimeInitFailed`（`docs/14` §3.2 的"runtime/模型格式不兼容"一栏）。**隔离由 OS 进程边界提供，与 `catch_unwind` 无关。**

2. **运行期 native 被 `SIGKILL`**：
   ```
   native 被杀后：运行时后端失败：写入 native stdin 失败（native 可能已退出）
   ```
   worker 随后以退出码 70 退出；宿主看到的是一次 `BackendFailed`，下一次请求才会重启（不重放）。

## 3. 与原设计的偏差及原因

### D-10（架构）三层进程：native 是 worker 的子进程，不是 C ABI 桥接

- **原建议**：`docs/14` §3.2 推荐 `runtime-bergamot` crate（`bridge.h` + `bridge.cpp` + `build.rs`）。
- **实际**：worker（Rust）以行模式 JSON 监督 `bergamot` CLI 子进程；行协议完全私有。
- **原因**：`docs/14` §3.3 明确给了替代方案；Bergamot 没有稳定的"单句 C ABI"，P3.0 已经用补丁把 CLI 改成行模式并验证过；本轮目标是**先把闭环与故障隔离跑通**，而不是先造一层 FFI。
- **代价**：多一层进程与一次管道往返（热路径实测没有可测差异：p50 13.17 ms vs P3.0 的 13.08 ms）；进程树更难解释；`ps` 里会看到两个进程。
- **影响**：native 死 → worker 退出 70，复用 P3.1-A 的 `WorkerExited` 语义，传输层零改动。
- **补做**：如果将来要 C ABI，只需替换 worker 内部实现，帧协议与 `RuntimeTransport` 不变（`docs/14` §7 要求的正是这一点）。

### D-11（卸载）`Unload` = 结束 native 进程，不是 native 内部卸载

- **原因**：Marian/Bergamot 没有"释放模型、保留进程"的可靠 API；`docs/14` §7 允许以"结束并重建 worker（这里是 native）"实现卸载。
- **代价**：卸载后重新加载要付 **725 ms** 冷启动（含 262–270 ms 快照）。
- **未证明**：native 进程内部是否真的把 RSS 还给了 OS——我们只证明了"进程消失"，没有做"卸载后 RSS 收敛"的进程内测量（`docs/14` P30-09 的原始问题仍未回答）。

### D-12（实现顺序）快照是"复制即校验"，不是"先全量校验再复制"

- **原建议**：§3.5 的顺序是"先核对四文件，再复制"。
- **实际**：先做**便宜的**元信息预检查（存在/非链接/大小），然后复制的同时算 sha256，比较的是副本字节。
- **原因**：这个顺序的保证更强（校验对象就是被打开的对象），并且省掉一次 49.5 MiB 读取：`model_preparation_ms` 从 766 ms → 262 ms。
- **代价**：坏文件会先被复制一遍再被丢弃（最多 49.5 MiB 的无效写），已用"删除半成品目录"处理。

### D-13（安全边界）0o400/0o700 不是安全沙箱

- 同用户的恶意进程仍可改写快照文件（`bt08` 就是**故意**这么做的，用来验证 worker 侧复核）。
- 没有使用 `openat`/目录 FD/seccomp/独立用户。因此不能宣称"对抗同权限本地恶意进程"。
- **补做**：P3.1-D 的租约 + 内容寻址仓库；更强隔离属于发行前安全评估。

### D-14（并发与排队）串行锁、无排队截止时间

- 仍是一把 `Mutex`、1 worker、1 in-flight；`docs/14` §1.1-2 指出的"第二个请求可能在锁上无限等"**没有修复**。
- 原因：队列与绝对 deadline 属于 P3.1-D；本轮把"加载/翻译超时分开"做了，但排队语义没做。
- 文档与代码注释都如实标注，不宣称支持排队超时。

### D-15（缓存身份）真实 NMT **不接缓存**

- `content_digest` 仍是"package@version#权重 sha256 前 32 位"，`docs/01` ADR-026 已写明**只能诊断、不得作缓存键**。
- 本轮没有把真实 NMT 接进 `translator-core` 的缓存/路由，所以不存在"用错身份命中缓存"的路径。
- **补做**：P3.1-D 的 `ResolvedExecutionPlan`。

### D-16（元数据）`Payload::Loaded` 只加了 4 个可选字段

`runtime` / `runtime_build` / `platform` / `native_pid`，全部 `#[serde(default, skip_serializing_if)]`，旧对端不受影响。四文件摘要集合**没有**进响应（它在 `ModelSpec.digests` 里随请求下发，worker 用它做打开前复核）；如果 D 阶段需要"身份回执"，再加可选字段。

### D-17（判定口径）金样本 21/24，不与 P3.0 的 23/24 直接比较

见 §2.5。特别声明：`code-01` 在 `must_contain` 口径下"通过"，但反引号实际被换成了中文引号——**这是判定口径的盲区，不是模型做对了**。P3.1-C 必须用"逐字节结构比对"而不是"包含某子串"来判定。

### D-18（进程复用）加载期 native 崩溃后 worker 仍可复用

- `docs/14` B-P0-04 写的是"进程失败不可重用"。
- **实际**：native 崩溃 → 该 native 被回收、`loaded=None`，**worker（监督者）仍可复用**，下一次 `Load` 会起新的 native。
- **理由**："不可重用"针对的是**持有模型状态的那个进程**（native）。监督者不持有 native 状态，只要 `loaded` 与 `snapshot` 被清干净，复用它不会带来脏状态；`bt06` 正是先让它崩一次、再用同一个二进制加载好模型翻译成功。
- **风险**：如果未来 worker 自己也持有 native 资源（例如共享内存），这条结论要重新评估。

### D-19（残留）SIGKILL 时的工作目录

- worker 的临时配置目录 `/tmp/nmt-worker-<pid>-<epoch>/` 在 SIGKILL 时会残留（几 KB 的 YAML）。
- 快照目录（49.5 MiB）由 `prune_stale_snapshots()` 按 pid 清理，不会无限堆积。
- **未做**：工作目录的自动清理（收益/复杂度不划算，先记录）。

## 4. 明确**未**证明的事

1. `{name}`/`{order_id}`/反引号能否被**保护并还原**（P3.1-C，SP-01～08）——本轮只证明了"它们现在会被破坏/被侥幸保留"；
2. 卸载后 native **进程内** RSS 是否收敛（我们只证明了进程消失）；
3. 并发 > 1 的行为、排队截止时间、single-flight、租约（P3.1-D）；
4. 真实 NMT 进入 `translator-api`/CLI 的端到端路径（P3.1-E）；
5. Linux CI 与多轮重复基准（P3.1-E / P3.3）；
6. PSS、`smaps_rollup`、分阶段（加载前/热推理/卸载后）峰值曲线（P3.3）；
7. 任何非 Linux 平台（P3.1-A 的平台门禁仍然生效：非 Linux 一律 `CapabilityUnavailable`）；
8. 权重再分发许可证（P3.4，仍为发布阻断项；本轮未分发权重）；
9. 快照在"源目录被不可信主体写入"下的实际强度（只讨论权限，没有对抗性实验）。

## 8. 下一阶段入口条件（P3.1-C）

进入 C 之前必须先定的三件事：

1. **判定标准换成结构比对**：`must_contain` 会漏掉"反引号被换掉"这类破坏（§2.5 第 3 点），C 的金样本必须比对"标记数量/位置/字面量"而不是子串。
2. **保护标记要选得让模型更难动**：P3.0/本轮都表明模型会吞 `{name}` 这类"像自然语言"的片段；C 要试多种占位符形态，并接受"某些形态就是不行"的结论。
3. **失败必须显式**：`strict_placeholder_restore` 要接到真实 NMT 的默认路径，失败返回 `IntegrityFailure`，不允许"看起来正常"的译文落库/缓存。
