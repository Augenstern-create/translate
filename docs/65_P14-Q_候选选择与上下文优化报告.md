## 1. P14-Q1 — 先审计 Best 是否真的选对

新增离线审计 `tools/quality/evaluate-candidate-selection.py`，用参考译文比较“整段 / 逐句 / Best 选中”：

| 指标 | 结果 |
|---|---:|
| 样本 | 50 段 |
| 选择器准确率（选中 chrF 较高者） | **62.00%** |
| 平均 regret（选中比 oracle 低多少 chrF） | **0.0224** |
| 选择分布 | 逐句 35 / 整段 15 |
| Best chrF | 0.4205（逐句 0.3987 / 整段 0.3917） |

**结论**：Best 整体 chrF 确有 +0.0218，但**“选对”只有 62%**；平均损失 0.0224 不算灾难，但不能把 Best 当成可靠判决器。最大错误样本：

| 段 | 选中 | Oracle | whole | sentence | regret |
|---|---|---|---:|---:|---:|
| paragraph-v1-0027 | 逐句 | 整段 | 0.5927 | 0.3453 | 0.2474 |
| paragraph-v1-0007 | 逐句 | 整段 | 0.8958 | 0.7318 | 0.1641 |
| paragraph-v1-0047 | 整段 | 逐句 | 0.2428 | 0.3607 | 0.1179 |

错误多发生在**短段落**：整段保留了上下文但输出没有标点，选择器却按“句数”偏向逐句。当前没有找到既提高 chrF 又普遍提高选择准确率的简单规则；不做过度拟合，保留现有选择器并记录 Q-052。

### 质量预算

已把 Best 从“所有 2+ 句段落”改成**风险预算**：

- 3 句以上、>500 字符、含数字/条件/否定才跑整段+逐句两个候选；
- 2 句普通段落单次推理；
- 显式 `ParagraphStrategy::Best` 仍强制比较。

这样不会为了小收益让所有短段落付 3× 延迟（Q-044/Q-052）。

## 2. P14-Q3 — 更强模型候选

- 当前可取得的 ONNX en→zh 候选（Xenova / onnx-community / skillsafe / TigreGotico）**都是同一 Helsinki opus-mt 权重的转换**，不是不同模型。
- `liam168/trans-opus-mt-en-zh` 无 ONNX、许可未声明；需要 torch/optimum 导出；未自动下载/安装。
- NLLB/M2M 是不同架构，tokenizer/language token/decoder 协议均与当前 Marian 引擎不兼容，需通用 seq2seq 后端，P14 未展开。
- 因此 **P14-Q3 没有产生“明显优于 opus-mt”的模型**；继续记录 Q-051，不把 fp32/fp16 冒充更强模型。

| int8 | 0.4535 | 0.4659 | 0.4205 | 默认 |
| fp32 | **0.4724** | 0.4645 | 0.4185 | 不默认 |
| fp16 | 0.4648 | 未跑 | 未跑 | 不采用（慢/内存高） |

## 3. P14-Q4 — 段落上下文实验

在 P14 中新增 `ParagraphStrategy::Context`：把前一句拼在当前句前送入模型，只取输出最后一个句段；若模型没有形成两个句段，则判定该句上下文失败并回退独立翻译，**不把回退伪装成成功**。

50 段对照：

| 策略 | chrF | 参考句覆盖 | 标点完整率 | fatal | 说明 |
|---|---:|---:|---:|---:|---|
| A 整段 | 0.3917 | — | 0.48 | 0 | 上下文完整，易截断 |
| B 逐句 | 0.3987 | 0.3848 | 0.58 | 0 | P12 基线 |
| C 句群 | 0.3909 | — | 0.50 | 1 | 长句组截断 |
| **Context（前一句）** | **0.4120** | **0.3989** | 0.60 | 0 | 有增益，但多数句回退 |
| Best（整段+逐句） | **0.4205** | **0.4111** | 0.60 | 0 | 当前最高 |

Context 的 **fallback 统计**：13/50 段 0 次回退、8/50 段 1 次、**29/50 段 2 次**（3 句里只有 1 句真正用了上下文）。这说明当前 Marian 经常把上下文和当前句合成一个输出，无法可靠分离。

**裁定**：Context 是**实验性失败/部分成功**，不默认启用；保留为 `ParagraphStrategy::Context` 供后续更强模型/更可靠抽取使用（Q-053）。不能用“取最后一句”的后处理掩盖模型不支持上下文的事实。

## 4. P14-Q2 — 最终质量

- 320 条 int8 仍为 **chrF 0.4659 / fatal 0 / 数字 1.0**（P14 没有新的全局默认变化）。
- 100 句 int8 仍为 **0.4535 / fatal 0**；fp32 0.4724 仍只在独立集更好。
- 50 段 Best 仍为 **0.4205 / 覆盖 0.4111 / fatal 0**。
- 聚合文本的 quality 现在按**最终文本**重算，不再把各子句的 fatal 直接相加；这修复了上下文/术语改写后“子句 fatal 但最终文本正常”的误报。

### 语义诊断

- `conditional_dropped` / `possible_omission` / `possible_hallucination` 保留；
- 100 句 int8/fp32 各只剩 1 条条件、1 条否定、1 条数字格式提示（启发式口径）；
- 中文数字等价（两小时三十分钟/百分之十五）不误报；
- 这些是**诊断**，不是语义证明。
