## 2. A4-1 双实例并发 + 卸载

命令：`p10_shared`（两个 `OrtNmtEngine::shared`，A/B 各 20 次并发，100 ms 后 A unload）。

| 指标 | 结果 |
|---|---|
| `shared_arc` | true |
| A 成功/失败 | **20 / 0** |
| B 成功/失败 | **20 / 0** |
| unload | 成功 |
| 卸载后 B 重载 | 成功，**212.6 ms** |
| pool_count | 1 |

结论：并发期间 unload 没有崩溃/死锁；B 的在飞请求完成，之后可重载。没有把 A 的 unload 静默成 B 的成功或失败。
证据：`tests/p10/shared.log`。

**NM-06：PASS（含并发）；NM-08：PASS（本轮双实例）。**

## 4. A4-3 内存预算对照

- ORT 估计值：**629,145,600 B**（600 MiB，配置 `steady_bytes`）。
- 1,000 次实测：RSS **424.7 MiB**、Private **413.1 MiB**；估计比实测 Private 高约 **216.9 MiB**（保守下界/预算，不是精确预测）。
- 预算测试：100 MiB → `OutOfBudget`；650 MiB → 构建成功；`nmt_ort_engines` 1 个。
- 结论：**预算行为 PASS；估计精度 PARTIAL**，不能把 600 MiB 当实测，也不能用 424 MiB 反推所有机器。

**NM-11：PASS（行为）/ PARTIAL（精度）。**

## 5. NM-09 崩溃隔离

- 当前 Windows ORT 与 SDK 同进程；没有独立 worker。原生崩溃会带走宿主，`catch_unwind` 不能证明 C/C++ 崩溃隔离。
- 本轮**没有**在测试进程里注入崩溃；也没有把它写成 PASS。
- **NM-09：BLOCKED（架构限制）**；要验证需独立子进程载体/故障注入，另批。

## 6. 取消语义

- ORT 没有请求级取消点：`timeout_ms` 被接受，但不会中断底层推理；调用方停止等待 ≠ 推理已停止。
- 不能强杀宿主/进程来模拟“取消”；不把 `N/A` 计 PASS。
- **NM-07：N/A（cancellation=unsupported）**，文档应明确告诉宿主。
