## 1. 目标

构建长期可扩展的英中翻译 SDK：高质量词典与短语、可组合规则、共享语言分析、
唯一 Planner、本地/远程模型统一兜底、经授权的持续学习与知识验证。

核心路线：

```text
用户输入
  → 结构/语言分析
  → 词典/短语/规则/约束证据
  → 统一 TranslationPlanner
  → Dictionary / Rule / LocalNmt / Remote / Mixed
  → 组装与质量检查
  → 翻译结果
  → （授权后）未覆盖记录 → 聚合 → 审核 → 版本化发布
```

## 2. 架构原则

1. 质量优先于模型调用次数与运行性能。
2. 词典与规则是长期核心资产，不是模型缓存。
3. 本地 NMT 与远程 API 都属于模型兜底；实际选择取决于质量、授权、成本、网络与隐私。
4. 一个 Planner 统一顶层决策；不得新增第二套 Planner/Router。
5. 词典、规则、Planner、执行层共享最小语言证据，不重复分析。
6. 模型译文不是正确标签；未经验证不得进入正式知识库。
7. 主翻译链独立可靠；学习链故障不得阻塞翻译。
8. 不为了重整而重写稳定模块；优先复用现有 API、词典、规则、ORT、ResourceStore、
   Runtime、缓存与诊断。
9. 默认不持久化翻译正文、不向第三方上传文本；学习与远程翻译是独立授权。
10. 不以词条数、规则数、日志量或模型调用下降代替可验证质量。

## 3. 工作包

| 工作包 | 内容 | 验收 |
|---|---|---|
| A0 | 真实源码核验：Word/Phrase/Sentence/Paragraph/Document/Local/Remote 路径；Planner/Routing/Coordinator 重复决策 | 路径与重复点有源码证据 |

| P20-K 基础 | 未覆盖记录、本地学习、候选提取、审核、发布/回滚 | 默认关闭；Raw/Verified 分离 |

## 4. 验收矩阵

### 架构

- AR-01 统一 Planner
- AR-02 共享语言证据
- AR-03 Dictionary 单词/多义/短语
- AR-04 Rules 完整覆盖才输出
- AR-05 Mixed 正确组合
- AR-06 Local NMT 复杂文本兜底
- AR-07 Remote 接口与授权边界
- AR-08 TextKind 与路由解耦
- AR-09 Cache 模式/路由/资源隔离
- AR-10 Diagnostics 可解释
- AR-11 API 兼容
- AR-12 质量不发生重大回归

### 持续学习

- KL-01 未覆盖原因可区分
- KL-02 仅在授权范围内保存
- KL-03 不同语义上下文不错误合并
- KL-04 词/短语/规则候选提取
- KL-05 Raw 与 Verified 区分
- KL-06 未验证模型输出不得发布
- KL-07 资源版本可追踪/回滚
- KL-08 新资源发布后缓存正确失效
- KL-09 学习数据可删除
- KL-10 未授权不持久化正文/不外发
- KL-11 新知识不引入重大错译
- KL-12 可衡量可靠覆盖与错误直出
