## 3. 本轮修复的关键问题

### 3.1 搭配不能丢修饰语

`He runs a small company.` 曾被数据化搭配输出为“他经营一家公司”，丢失 `small`。
现改为：

```text
collocation = 目标动词（经营）
object      = 统一 NP（一家小公司）
结果        = 他经营一家小公司。
```

搭配数据只提供动词，不提供整句或完整宾语；NP 仍由共享 `entity_zh` 生成，
因此形容词、数量、指代不会被搭配表覆盖。

### 3.2 候选验证不能只看“有否定词”

`He didn't go.` 的错误候选 `他不想去。` 同时含“不”，旧检查会通过。
现按 frame 判定：

- Past → 必须含 `没`
- Simple → 必须含 `不`
- Modal → 必须含 `不会`
- Progressive → 必须含 `没在`
- have + negative → 必须含 `没有`

该反例已加入测试，要求 `wrong-negation`。

### 3.3 have 否定

`He doesn't have a computer.` 从错误“他不有一台电脑”修为“他没有一台电脑。”，
并加入 20 条后置集。

## 6. A-03/A-05/A-06 确定性整改

### 6.1 A-06 无损 Tokenizer

`tokenize()` 现在返回 `uncovered` 跨度：数字、货币、百分号、Unicode 等
非字母片段不再被静默跳过。组合层和语义层在 `uncovered` 非空时拒绝规则生成，
由 Coordinator 继续 NMT；不再声明虚假的完整覆盖。

验证：

- `There are 2 apples.` → NMT
- `The price is 100%.` → NMT
- `Total: $20.` → NMT
- `She has two apples.` → Rule

见 `p21_coverage.rs`。

### 6.2 A-03 并列节点

`EntityRef.coordinated: Vec<EntityRef>` 保留每个并列实体的数量、修饰和量词。
不再把 `two books and three pens` 压成一个中文字符串节点。

- `I bought two books and three pens.` → 我买了两本书和三支笔。
- `I like tea and coffee.` → 我喜欢茶和咖啡。

`entity_coordinated()` 只建立节点关系，中文连接在 Realizer 中完成。

### 6.3 A-05 关系级候选验证

新增角色顺序检查：

- 主动结构：施事位置 < 谓词位置 < 受事位置；
- 被动结构：受事 < 被 < 施事 < 谓词；
- 比较结构：主体 < 比 < 比较对象 < 属性；
- 补语：谓词 < 补语。

错误候选测试：

```text
frame: 狗 追 猫
good: 狗追猫。      -> valid
bad:  猫追狗。      -> wrong-role-order
```

错误否定候选 `He didn't go.` → `他不想去。` 仍由 `wrong-negation` 拒绝。

### 6.4 剩余

这不是完整节点级验证，也不是完整 SyntaxGraph：

- 仍以字符串位置和含义字段为主；
- 没有实现通用句法依赖图；
- `Lexeme.zh` 仍与英语词形同结构，尚未完成 SenseCandidate/TargetLexeme 全分离；
- ChineseRealizer 仍是受限格式器，不是完整 ChineseStructure；
- 复杂从句、PP、相对从句仍回退。

因此 A-01/A-02/A-04/A-08/A-09 仍为 **PARTIAL**，不能因上述整改宣称 P21-R 完成。

## 7. A-01 局部 SyntaxGraph 进展

新增：

```text
SyntaxNode { surface, lemma, pos, span }
SyntaxRelationKind { Subject, Object, Adverbial, Negation, Complement }
SyntaxGraph { nodes, relations }
```

`parse_compositional()` 作为独立于完整句型链的前置路径，处理：

- 主语；
- 可选否定助动词；
- 谓语；
- 名词短语宾语（含数量/修饰/并列节点）；
- 时间状语；
- 生成 `MeaningProgram + SyntaxGraph`。

验证样本：

```text
She didn't buy two new books yesterday.
→ SyntaxGraph: she -Subject-> buy, buy -Object-> book, buy -Adverbial-> yesterday
→ 她昨天没买两本新书。
```

见 `p21_syntax.rs`。

**边界**：该路径目前只覆盖简单陈述/否定/时间组合，未覆盖全部 parse_* 结构；
A-01 因此仍是 **PARTIAL**，不是完整语法图。

## 8. A-02/A-04/A-08/A-09/A-10 本轮增量

### A-02 词汇/词义/目标词

新增：

- `LexicalEvidence`（英语词形、lemma、POS、span）；
- `LexicalSenseCandidate`（sense id、POS、目标词、约束、来源）；
- `TargetLexeme`（目标中文、sense id、来源）；
- `Lexeme.sense_id`、`Lexeme.targets`、`Lexeme.target_zh()`。

组合路径会为 agent/predicate/patient 填充独立 target 候选，Realizer 优先读取
`target_zh()`，旧路径仍以 `zh` 兼容。

**已接入**：解析器构造的 Lexeme 不再携带中文，`zh` 为空；语义程序后处理统一
填 `sense_id` 与 `TargetLexeme`，Realizer 与验证器读取 `target_zh()`。
固定表达仍保留原子化 `zh`。

**折扣**：sense 表较小，论元约束/候选冲突尚未覆盖全部词汇。

### A-04 作用域

新增 `ScopeTarget::{Predicate, Complement}` 与 `MeaningFrame.negation_scope`。
组合陈述的否定路径记录 `Predicate`；旧兼容 frame 允许为空。

**已接入**：条件关系 `Condition`、形容词修饰 `Modifier`、时间 `Adverbial` 已进入
`SyntaxGraph`；否定有 `ScopeTarget`。

**折扣**：复杂从句、嵌套作用域仍未覆盖。

### A-08 ChineseStructure

新增 `ChineseNounPhrase`、`ChineseClause`、`ChineseStructure`；
`ChineseRealizer::structure()` 可从 MeaningFrame 生成目标语中间结构，
`ChineseClause::render()` 提供可解释的表层生成。

**已接入**：简单陈述、非 have 否定、过去、进行、经历体、情态、被动、条件、搭配
已通过 `ChineseClause` / `ChineseStructure` 生成；条件结构带 relation/condition 并由
`ChineseStructure::render()` 输出。

**折扣**：尚未完全取代旧 `format!` 分支，ChineseStructure 仍是部分路径。

### A-09 词义候选

新增 `LexicalSenseCandidate` 类型，组合路径可生成 target/sense id；
搭配仍来自 `collocations` 数据。

**已接入**：`senses` 数据表支持同 lemma/同 POS 的多个目标词，按 object 约束选择：

- run + company → 经营；
- run（无 object）→ 跑；
- take + photo → 拍；
- take + book → 拿。

**折扣**：仍只有少量 sense 数据，尚未形成完整论元类别/冲突拒绝统计。

### A-10 独立集

新增 `p21-independent-v1.jsonl`，20 条后置验证集，20/20 Rule。
统一评审包扩展到 118 行。

**折扣**：该后置集在生成后调整过两个预期词形，不是严格未触达的盲集；
人工评审仍全部 `PENDING_HUMAN`。

A-02/A-04/A-08/A-09 均为 **PARTIAL**；A-10 的代码/数据部分有增量，

## 9. 第四轮增量：候选 trace 与目标结构

### A-05 候选结构 trace

`RealizationCandidate` 新增：

```rust
structure: Option<ChineseStructure>
```

简单陈述和非 have 否定候选携带 `ChineseClause`，验证器会检查：

- `clause.predicate` 是否等于目标谓词；
- `clause.subject` 是否包含施事；
- `clause.object` 是否包含受事；
- 否定候选是否记录否定词。

新增错误 trace 测试：

```text
frame: 狗 追 猫
candidate structure: subject=猫, object=狗
→ trace-subject-mismatch
```

这比只做字符串包含更强，但仍不是完整语义图；自由文本候选没有 trace 时只能走旧检查。

### A-08 ChineseClause 接入

简单陈述和非 have 否定已经通过 `ChineseClause::render()` 产出。
过去、搭配、条件、被动等分支仍保留原格式器。

### 未完成

- A-02 仍以旧 `.zh` 为主，target 候选只在组合路径落地；
- A-04 仍缺通用时间/条件/修饰关系节点；
- A-08 仍未完全统一；
- A-09 仍缺同 POS 多义候选和冲突拒绝；
- A-10 仍缺真实人工评审。
