## 4. R2：MeaningFrame 深化

新增/使用字段：

- `EntityRef.quantity`：two/three… + 量词；
- `Modifier::Time/Place`；
- `QuestionType::YesNo/Wh`；
- `TenseAspect::Past/Progressive/Imperative/Modal`；
- `Polarity::Negative`；
- `complement`（want to **go**）；
- `source_spans`；
- `RejectionReason`（PP 附着、嵌套/未解决代词、未知词等）。

作用域：

- `I don't want to go`：否定在 WANT，complement=GO，Realizer 输出“我不想去”；
- `He didn't go`：Past + Negative，输出“他没去”；
- `She isn't reading`：Progressive + Negative，输出“她没在读”；
- `I can't swim`：Modal + Negative，输出“我不会游泳”。

来源：每个 frame 的谓词/实体保留 span；拒绝保留 token span。

## 5. R3：中文名词短语与量词

`ChineseRealizer::entity_zh` 统一处理：

| 英语 | 中文 |
|---|---|
| a book | 一本书 |
| two books | 两本书 |
| three tickets | 三张票 |
| a new phone | 一部新手机 |
| my phone | 我的手机 |
| this blue bag | 这个蓝色的包 |
| the light blue bag | 浅蓝色的包 |

量词来自 `en-zh.composition.json` 的 `classifier` 数据；没有可靠量词时
`a/an + 名词` 结构拒绝组合，不默认“个”。

**限制**：量词表只覆盖高频名词；同名词的多个量词/语体差异未建模（Q-100）。

## 6. R4：否定、情态与体貌

已实现：

- `不`：一般否定/形容词否定/意愿否定；
- `没`：过去动作否定（`didn't`）；
- `不会`：can 否定；
- `没在`：进行时否定；
- `正在`：进行时；
- `了`：已完成/过去事件；
- 无显式体貌：一般现在/状态。

示例：

- 我不知道。
- 我不想去。
- 他没去。
- 我不会游泳。
- 她没在读。
- 我不累。
- 她正在读一本书。

**未实现**：过/着、全部完成体/经验体、被动、比较、复杂结果补语（Q-100）。

## 7. R5：语序、修饰与并列

- 时间语序候选：
  - `她昨天买了一部新手机。`
  - `昨天她买了一部新手机。`
- 量词/形容词/领属/指示已统一到 `entity_zh`；
- 并列祈使：`请打开门，并关窗。`
- 并列只处理已验证的 `please ... and ...`；其他 `and` 仍回退 NMT；
- PP 附着、嵌套否定、未解决代词继续拒绝。

## 13. 未解决

## 14. 结论

P21-R 证明了第一轮统一迁移是可行的：

- 同一套 `MeaningFrame + ChineseRealizer` 可以接收多个 P19 英语结构；
- 词汇替换（two/three/new/blue/my/this）不需要新整句模板；
- 量词、语序、否定、情态、体貌从 P19 的分散字符串生成收敛到共享实现；
- 固定表达/短语/条件保留稳定路径，未强行迁移；
- 320 无回归、2 条改善，工程测试全绿。

因此结论为 **Conditional**：统一中文生成的核心闭环已建立，但迁移不完整、
中文生成范围有限、人工评审未完成，不能宣称自然度或全面统一已通过。
