## 5. A4-4 独立子进程崩溃 PoC

`p10_crash` 父进程只启动**自己的子进程**（`--child`），不向主测试进程或其他用户进程注入：

| 子进程 | 结果 |
|---|---|
| access violation 子进程 | exit **3221225477 / 0xC0000005**，父进程继续 |
| 正常子进程 | exit 0，stdout `child-ok` |

**能证明**：独立子进程异常退出可被父进程观察，父进程不受影响。
**不能证明**：当前生产 ORT 与 SDK 同进程时具备崩溃隔离；`catch_unwind` 不能拦截 C/C++ access violation。
**结论：NM-09 仍 BLOCKED；不把 PoC 写成生产 ORT PASS。** 证据：`tests/p10/crash.log`。

## 7. 架构建议

- 不重构生产 ORT；保持进程内低延迟路径。
- 若宿主需要强隔离/可强制中断，评估可选独立 ORT worker；代价是 IPC、模型进程内存与维护成本。
- 当前证据不支持“进程内 ORT 已崩溃隔离”，也不支持把 worker 设为默认。
