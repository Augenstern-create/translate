### 1.1 容易被“测试全绿”掩盖的边界

以下是**需要源码与新增测试才能确定的风险**，不是已经确认存在的 bug：

1. **读帧线程 detach 后的生命周期**：报告描述“最多等待 200 ms，然后 detach”。这保证调用方不阻塞，但**不保证线程退出**。应验证 shutdown/超时/Drop 都先关闭所有管道端，并且读线程没有在持锁回调或阻塞 IO 中无限等待。对重复 spawn→timeout→shutdown 进行线程数趋势测试。
2. **锁覆盖等待时间**：`ProcessTransport` 用一把 `Mutex` 串行所有请求。若锁等待不受 timeout 约束，第二个请求可能在第一个慢调用期间无限等待，尽管其自己的 `request_timeout` 已经到期。B 应明确记录此限制；D 通过队列截止时间解决。
3. **模型 revision 的回复一致性**：目前加载回复携带 revision。B 需要防止旧 worker、错模型、错配置仍返回合法结构的 `Translated`；宿主至少持有期望的 revision，并对 worker epoch/当前加载状态进行关联检查。
4. **原生 stdio 污染**：C++ 依赖可能写 `stdout`、调用 `printf()` 或日志输出。帧协议要求 stdout 纯净；B 必须明确将 native 日志重定向到 stderr，且在首次模型加载前设定。
5. **异常退出后的资源回收**：`ps` 一次性无残留是有价值的证据，但还应在“输出管道关闭、父进程 shutdown 与 worker 崩溃同时发生、连续 100 次异常”下验证文件描述符与线程数没有持续增长。
6. **超时默认值 10 s**：对 44 MB 级热缓存模型可能够用，但不能直接用于磁盘冷缓存、慢设备、校验时间及排队等待的总上限；需要给各阶段明确截止时间。
7. **sha256 只是时点验证**：即使 `verify_paths()` 在 spawn 前执行，worker 之后仍按路径 `open()`；路径替换和文件原地改写仍可产生 TOCTOU。B 的快照机制是实质性修复，而不是更频繁地检查路径。
8. **协议异常与数据敏感性**：坏帧、错误文本、stderr 尾部可能含用户内容；环形缓冲限制了长度，不等于已经脱敏。对外诊断要保留原始文本的默认关闭策略。

## 3. P3.1-B 技术实施方案

### 3.1 B 阶段范围与非目标

**必须实现**：

- `nmt-worker --bergamot` 不再返回 Mock/不可用；通过进程内 C++ 适配层调用真实 Bergamot/Marian。
- 基于 `fixtures/nmt/models.lock.json` 的四文件集合（model / src vocab / target vocab / lex shortlist）验证、快照、配置生成。
- `Load` / `Translate` / `Unload` / `Health` / `Shutdown` 按现有帧协议工作，且 worker epoch、模型 revision 可核对。
- “真实成功路径”和“真实异常路径”均由 Rust 测试父进程调用，确认崩溃不会杀宿主。
- 收集真实模型加载、首次翻译、热翻译、卸载/worker 退出后的内存指标；保留 Mock 回归。

**暂不声称完成**：

- `Translator::translate()` 公共门面完整接线（原计划 P3.1-D/E）。
- 全量 `{name}`/反引号的安全翻译（P3.1-C）。
- single-flight、热模型复用池、运行期 TTL/LRU、完整执行计划摘要（P3.1-D）。
- Android/macOS/Windows 支持、权重可公开分发、正式翻译质量评分。

### 3.2 推荐代码边界

```text
crates/
  translator-runtime/             # 现有 IPC/Transport；不直接依赖 C++
  runtime-bergamot/               # 建议新增：受限 C ABI + Rust 安全桥接，Linux feature gated
      include/bridge.h
      native/bridge.cpp
      build.rs
      src/lib.rs
      src/error.rs

crates/translator-runtime/src/bin/nmt-worker.rs
      --mock                      # 保留独立故障注入路径
      --bergamot                  # feature + Linux 限定

tools/p3/
  build-bergamot.sh               # 复用 P3.0 锁定的参考构建
  prepare-model.sh
  nmt_baseline.py
```

`translator-runtime` 不应反向依赖 `translator-api`。如果 `runtime-bergamot` 与 `translator-runtime` 出现循环依赖，让 worker bin 位于独立 `apps/nmt-worker/` crate 中，由组合层单向依赖二者。

不要让 Rust 直接拥有未知线程语义的 `marian::...`/`bergamot::...` C++ 类型。由 C++ bridge 持有 native 句柄，并提供明确的创建、翻译、释放函数；Rust 仅使用 opaque handle。

### 3.3 原生桥接契约（建议，不是已实现代码）

```c
/* 头文件设计草案：只展示 ABI 方向，非编译验证产物 */
#pragma once
#include <stddef.h>
#include <stdint.h>

typedef struct bt_model bt_model;

typedef enum bt_status {
    BT_OK = 0,
    BT_INVALID_ARGUMENT = 1,
    BT_MODEL_ERROR = 2,
    BT_TRANSLATION_ERROR = 3,
    BT_OUT_OF_MEMORY = 4
} bt_status;

bt_status bt_create(const char* config_path, bt_model** out_model);
bt_status bt_translate(bt_model* model,
                       const uint8_t* input, size_t input_len,
                       uint8_t** output, size_t* output_len);
void bt_free_buffer(uint8_t* ptr);
void bt_destroy(bt_model* model);
```

契约要求：输入/输出以长度表示，不假设 NUL 终止；所有输出由 bridge 专属释放函数释放；`bt_create` 失败时不留下半初始化句柄；C++ 可捕获的 `std::exception` 在 bridge 内转成受控状态，**但 `abort()`、SIGSEGV 仍只能靠进程隔离**。Rust FFI `unsafe` 块要有安全不变量注释，并使用有限的 native 锁/actor 防重入。

**替代方案**：如果 Bergamot 现有 API 无法稳定通过 C ABI 单句调用，B 阶段可将参考 CLI 的长驻翻译服务作为独立 worker 内部实现；只要满足上述 Load/Translate/Unload 及故障隔离契约，不强求先构造通用 C ABI。不得把临时 JSON/行协议暴露给 SDK 上层。

### 3.4 ModelSpec → Bergamot 配置

在 worker 内使用**白名单、类型化配置生成**，例如：

```rust
struct BergamotOptions {
    cpu_threads: usize,  // 默认 1
    beam_size: usize,    // P3.0 基线为 1
    max_input_chars: usize,
    source_language: String,
    target_language: String,
}
```

在 `Load` 时由已验证 Manifest 和模型快照生成配置，禁止原始用户提供任意 Marian CLI/YAML 配置片段。路径按实际文件名/目录安全拼接，生成时拒绝非 UTF-8 与不可接受的特殊路径，或使用安全的 YAML 序列化方式防止注入。

保持与 P3.0 的 `--cpu-threads 1`、beam=1、词表路径、shortlist 配置一致；P3.0 的参考 CLI 译文应作为第一份对照。其它选项（线程池大小、分句/最大输入长度、短名单）需要显式加入 `ModelSpec`，但不要在这轮为所有 Marian 选项建立通用配置系统。

### 3.5 模型文件一致性：拍板采用“隔离快照”

**B 采用 worker 可见的私有、只读、不可变模型快照**，不是简单的“先 `sha256(path)` 后 `open(path)`”。建议按以下步骤：

1. Resource Store 提供已安装的 `id@version` 目录，禁止加载任意可写外部路径作为生产资源。
2. 加载时在受限 staging 目录内生成新快照（同文件系统内复制，**不要因性能原因直接硬链接到外部可写原文件**）。
3. 在新快照上核对四文件大小与 SHA-256，拒绝符号链接、非常规文件、路径穿越与重复角色。
4. 在本次校验之后**不再修改该快照**；尽可能用独占目录权限保护，并让 worker 的打开路径只指向快照内文件。
5. worker 内打开前再次验证快照文件元信息与摘要，并将已打开模型的身份记录在 loaded state；如果源目录可由不可信主体写入，仅 Unix 文件权限并非强安全沙箱，必要时采用 `openat`/目录 FD 或更强的访问隔离。
6. `Load` 成功后才允许 `Translate`，并将本次模型 digest 绑定到 worker 状态与后续回复。
7. 退出时清理临时快照；异常崩溃残留交给仓库恢复器按身份和租约清理，不由其他运行中请求随意删除。

这种方案可能增加约 50 MB 级复制 I/O 与磁盘占用，是安全换成本的权衡。**应测量快照构建成本**；未来 D 阶段可改为“经校验的不可变内容寻址仓库 + 租约”，避免每次加载复制。只读权限不能防止同一用户恶意进程改写，不能据此宣称具备对抗同权限恶意本地进程的完整安全保证。

### 3.6 分阶段超时与 worker 状态机

**明确区分四个时间预算：**

| 操作 | 建议初值（可配置） | 超时后 |
|---|---:|---|
| 进入串行执行队列 | 暂无独立队列；只允许受控单请求，排队超时留给 D | 不要宣称已支持 |
| 加载模型 `Load` | 30 s | 杀 worker，废弃加载状态 |
| 单次 `Translate` | 15 s | 杀 worker，原请求返回 Timeout |
| `Shutdown` | graceful 500 ms + TERM 500 ms | KILL + `wait` |

以上**仅建议初始配置**，不得将它们当作已测 SLA。加载时间还应单列“快照复制+sha256”与“worker native 初始化”；用户端到端耗时是两者之和。P3.0 的 605.9 ms 不包含这些新增开销。

worker 状态建议：

```text
Stopped → Starting → Ready/NoModel → Loading → Loaded → Translating
   ↑           │                       │          │
   └── Crashed/TimedOut ←──────────────┴──────────┘
Loaded → Unloading → Ready/NoModel
Ready/NoModel / Loaded → ShuttingDown → Stopped
```

`Load` 不得接受正在不同 revision 上执行的请求；`Unload` 失败则 worker 标记为不可复用；任何原生内存损坏迹象禁止继续使用同一 worker。

### 3.7 运行时版本与完整身份

B 的 `Load` 至少返回：`runtime_name`、Bergamot commit / Marian 子模块 commit、平台、`model_revision`、四文件摘要集合、CPU 线程数、beam size、worker epoch。若现有 `Payload::Loaded` 不能承载全部内容，可以添加**向后兼容的可选元数据字段**；不要把 A 阶段的 `package@version#sha256前缀` 直接升级为正式缓存键。

缓存身份完整版在 D 才生成：

```text
ResolvedExecutionPlan =
  engine id + runtime build/ABI + model package revision
  + model/src_vocab/trg_vocab/lex digest
  + source/target + decoding params
  + rules version + term table content digest
  + normalization/pipeline version + privacy domain
```

当前尚无 `content_digest` 的所有输入来源时，应明确 **cache disabled for real NMT** 或使已加载模型快照版本唯一决定当前会话的缓存范围，不能声称跨版本缓存安全。

### 4.1 B 与 C、D、E 的界线

- **B → C**：真实 NMT 可翻；尚不能把模板变量译文标记为安全。C 必须把 P3.0 的负面样本变成“严格保护/恢复”的正向回归样本。
- **C → D**：占位符安全后，再实现 `LocalNmtEngine` 在核心路由中的真实注册、model lease、single-flight、cache plan；否则容易把错误译文缓存成“正确”。
- **D → E**：通过 SDK 门面与 CLI 的端到端真实翻译，加 Linux CI、打包、性能/质量报告。

## 6. 性能/内存测量口径

必须分别记录：

1. `model_preparation_ms`：从资源包确认到创建校验快照；
2. `worker_spawn_ms`：创建进程并完成协议握手；
3. `native_load_ms`：创建 Bergamot 模型、Tokenizer 和工作区；
4. `first_translation_ms` 与 `warm_translation_p50/p95/p99`；
5. `host_rss`, `worker_rss`, `worker_vmhwm`、卸载后（worker 仍活着和 worker 退出两种路径）的内存；
6. 模型原始磁盘大小、快照体积、额外的映射页与动态库依赖。

`host_rss + worker_rss` 仅是简单相加，不等于实际物理内存增量；PSS 可在后续阶段通过 `/proc/<pid>/smaps_rollup` 补充。每次基准必须记录 sample size、CPU、线程数、beam、版本锁与是否热页缓存。**不能以“IPC mock 0.016 ms”推断真实翻译端到端性能，也不能以 43.8 MB 权重推断总峰值仅几十 MB。**

## 7. 需要开发者明确报告的偏差与不接受的捷径

- 如果 C++ API 无法在 worker 内安全 `Unload`，允许“结束并重建 worker”实现卸载，但必须将此行为和冷启动代价明确记录。
- 如果模型快照复制带来明显冷启动时间或磁盘成本，可以进行 benchmark 并提出内容寻址仓库优化；**不得退回裸路径 check→open 然后宣称 TOCTOU 已解决**。
- 如果真实 worker 复用 P3.0 CLI 行式补丁作为内部过渡实现，只能在 worker 私有实现中使用；对外仍需现有带版本的帧协议与稳定的 RuntimeTransport trait。
- 不允许将 native `abort()` 捕获能力归功于 `catch_unwind` 或 Rust 线程；崩溃隔离是 OS 进程边界提供的。
- 不允许让 `--all-features` 构建要求所有平台都有 Bergamot 依赖而破坏现有无模型、纯 Rust 的默认构建路径。
- 真实 NMT 不得未经授权自动退回远程 LLM；资源缺失只返回建议安装或显式错误。
- 许可证未完成审核，不把 Mozilla 权重打进公共发行包或 Git 仓库。

## 8. 建议新增的 ADR（按实际 docs/01 编号顺延）

> 据 `docs/13`，目前 ADR-029 已用于“严格占位符完整性（Proposed）”。以下仅给出**标题/决策内容**，不预占数字编号；写入 `docs/01` 时先核实最后实际编号。

- **隔离快照优先于路径二次校验**（Proposed → B 验收后 Accepted）：模型的身份绑定到实际 worker 可访问的校验快照，而不是只绑定 Manifest 中的字符串。
- **真实 Bergamot 默认单 worker**（Proposed）：延续 P3.0 单线程内存基线，新增并发必须提供内存/延迟证据。
- **IPC 协议与原生桥接独立版本管理**（Proposed）：`PROTOCOL_VERSION` 是父子进程协议版本，C ABI 版本是 worker 内部边界；二者不应混用。
- **加载/翻译/排队截止时间分离**（Proposed）：B 先实现加载与推理的配置化超时，D 再实现队列截止时间。
