## 1. 执行摘要

本轮从真实源码核验开始，完成了 P17-A 的核心架构收敛：

1. **唯一规划入口**：`planner::plan_request` 决定请求结构/执行形状，
   `planner::TranslationPlanner` 决定引擎与回退；`routing` 退化为兼容导出。
2. **共享语言证据**：新增 `LanguageEvidence`，把 span、词义候选、模式命中、
   数字/占位符/术语约束、上下文身份交给诊断与学习链。
3. **混合执行可解释**：段落/文档逐单元记录 Dictionary / Rule / LocalNmt / Remote

   `RemoteFallbackPolicy`，默认禁用；远程回退需独立显式授权。
5. **上下文选义归位**：从 API 旁路移入 Coordinator，统一策略、缓存、术语、
   质量与取消链。
6. **可取消入口统一**：`translate_cancellable`、诊断入口与 JNI 不再绕过结构规划。
7. **学习链基础**：新增 `translator-learning`，默认关闭；支持隐私分级、后台记录、
   聚合/候选、Raw→Verified→Released、`knowledge.json.v1` staging 与
   ResourceStore 安装/激活/回滚。
8. **质量保持基线**：320 句 chrF **0.5074** / BLEU **0.5060** / fatal 0 /
   NMT **300** / Rule **22**，与 P16-R 完全一致；100 词与 40 模板 NMT **0**。

未完成且不能写成完成的内容：P18-L 词库/短语/搭配扩充、P19-G 参数化与组合规则、

### 2.2 核验前的主要重复决策

| 位置 | 核验前行为 | 问题 |
|---|---|---|
| `Translator::run_options` | 自己判断 Word context / Paragraph Best / Context / plan | 与 Coordinator 路由并列，形成第二套顶层决策 |
| `Coordinator::run_inner` | 调 `routing::select`，自己再处理词典→NMT 回退 | 策略分支散落在 routing + coordinator |
| `Translator::try_context_word` | 在 API 层直接查词并组装结果 | 绕过规则/缓存/术语/质量/取消；`RemoteOnly` 也可能被旁路 |
| `translate_cancellable` / JNI | 直接调 Coordinator 单路径 | 段落/文档不经过 Planner，模板/上下文选义不生效 |
| 远程结果 | 实际远程仍可能标成 `LocalNmt` 路由 | 诊断与缓存隐私域不准确 |
| 词典 miss 回退 | 回退键未读回 | 每次请求都重新尝试词典并重新推理（Q-065） |
| 模板路由 | `capability=Nmt`，`route=Rule` | capability 语义粗糙（Q-066，仍保留） |

### 2.3 核验后的统一路径

```text
Translator API
  → plan_request(text, options)               # 结构/形状唯一入口
  → run_options_cancellable / run_plan
  → Coordinator::run_inner
      → 规则 / 模板
      → try_context_word（仅 Planner 判定可走词典时）
      → language_evidence
      → TranslationPlanner::resolve           # 引擎选择唯一入口
      → 保护 / 缓存 / 执行 / 回退
      → 还原 / 术语 / 质量
      → 诊断（evidence + unit traces）
  → 聚合（段落/文档）
  → 可选 LearningRuntime.submit（后台、非阻塞）
```

## 3. A1：共享语言证据

新增 `crates/translator-core/src/evidence.rs`：

| 类型 | 内容 | 用途 |
|---|---|---|
| `TextSpan` | 规范化原文字节区间，越界/非 UTF-8 边界安全 | 诊断、学习逐单元定位 |
| `UnitKind` | Word/Phrase/Clause/Sentence/Paragraph/Literal | 比 TextKind 更细的单元类型 |
| `SenseCandidate` | headword/definition/POS/source/confidence | 词典证据，不复制完整入口 |
| `PatternMatch` | Template/Phrase/Term/Rule，`complete` 表示完整覆盖 | 模板/规则证据 |
| `TranslationConstraint` | 数字/占位符/URL/代码/术语/glossary/完整覆盖 | 执行层必须满足的约束 |
| `ContextRef` | 上下文身份 + 字符数，不保存正文 | 诊断/缓存/学习 |
| `LanguageEvidence` | 以上事实的聚合 | Planner/诊断/学习共享 |

设计边界：

- 不引入完整自然语言 AST 或语义图；
- 复用 `TextKind`、`TranslationConstraint`、`ProtectedSpan` 等既有概念；
- 证据**不直接决定**引擎；Planner 仍按策略与结构决策；
- 单词/短语才做 provider 词义预取，整句不预查词典，避免“句中有词条”被误判为整句可词典翻译；
- 模板命中会把完整覆盖写入证据，供诊断/学习使用。

诊断新增：

- `TranslationDiagnostics.evidence: Option<LanguageEvidence>`
- `TranslationDiagnostics.fallback_reason: Option<FallbackReason>`
- `TranslationDiagnostics.units: Vec<UnitExecutionTrace>`，见
  `crates/translator-core/src/diagnostics.rs:55`。

## 4. A2：统一 Planner

### 4.1 两层但同一模块

`planner.rs` 现在承担两件互补的事，不再有第二套 Router：

1. **请求形状**：`PlanShape { Single, Multi, ParagraphBest, ParagraphContext }`，
   由 `plan_request` 返回；
2. **引擎选择**：`TranslationPlanner::resolve` 只在这里处理策略、能力、语言对、
   词典优先与远程授权；`routing.rs` 仅保留旧路径兼容导出。

### 4.2 策略语义

| 策略 | 行为 |
|---|---|
| `AutoLocalFirst` | 单词/短语先词典；否则本地 NMT；本机无模型时仅按 `RemoteFallbackPolicy` 授权回退 |
| `DictionaryOnly` | 只允许词典；不回退 NMT/远程 |
| `LocalOnly` | 只允许本地 NMT；绝不联网 |
| `RemoteOnly` | 只允许已授权远程；插件自身仍校验联网授权 |
| `ExplicitEngine` | 指定引擎；能力由引擎描述推断 |

`AutoLocalFirst` 不再被 `is_remote_allowed()` 视为远程允许；远程回退是独立配置
`TranslatorBuilder::remote_fallback(RemoteFallbackPolicy)`，默认 `Disabled`。

### 4.3 TextKind 与路由解耦

- `TextKind` 只表示输入组织方式；
- 单词可由模板/规则完整覆盖；
- 句子可由词典/模板直接完成；
- 段落/文档可以由 Mixed 逐单元组合；
- `TextKind` 不再隐含“必须 NMT”。

证据：`crates/translator-api/tests/p17_architecture.rs` 的
`段落混合执行保留逐单元决策轨迹`、`文档内词典规则模型可以混合并保留代码块`。

## 5. A3：本地/远程统一兜底

### 5.1 路由与统计

- `TranslationRoute` 新增 `Remote`；
- `RouteStats` 新增 `remote_calls`、`remote_fallbacks`；
- `nmt_calls` 只计本地 NMT，`remote_calls` 只计远程；两者都计入模型调用比例；
- 远程回退成功会写回远程缓存键，重复请求不再重复计费。

### 5.2 授权边界

- 默认 `RemoteFallbackPolicy::Disabled`：即使注册了远程插件，`AutoLocalFirst`
  也不会把原文发出去；
- `OnLocalUnavailable`：仅本机无模型时；
- `OnLocalFailure`：本机无模型或本地执行失败时；
- `RemoteOnly` 仍需远程插件自身的联网授权；
- 学习授权与远程授权完全独立；`allow_remote_upload` 在本版本**不触发任何网络请求**。

### 5.3 已验证行为

`p17_architecture.rs`：

- 远程回退默认关闭：返回 `ResourceNotInstalled`，`remote_calls=0`；
- 显式 `OnLocalUnavailable`：`route=Remote`、`fallback_reason=EngineFallback`；
- 本地注入失败 + `OnLocalFailure`：`nmt_calls=1`、`remote_calls=1`、
  `remote_fallbacks=1`；
- 远程回退重复请求命中缓存，`remote_calls=1`。

## 6. A4：Mixed 执行

### 6.1 逐单元轨迹

`UnitExecutionTrace` 记录：

- 单元序号、span、UnitKind；
- route、engine_id、capability、reason；
- 是否真正调用模型、是否缓存命中、fallback_reason。

段落与文档聚合后，`diagnostics.route` 在路由不同时为 `Mixed`，
`diagnostics.units` 保留逐单元事实；不再只有一个模糊的聚合引擎。

### 6.2 段落/文档行为

- 段落：`Whole/Sentence/Group/Best/Context` 保留；
- 文档：标题/列表/引用/普通段落/代码块保持结构；
- 文档中的单句普通段落现在按 Sentence 规划，可使用模板/词典；
- 代码块仍原样保留；
- 文档段落失败仍保留原文并写 `SegmentFailed`。

### 6.3 验证

- 段落 `hello / Good morning. / This is a complex sentence.`：
  `units=3`，route 分别为 Dictionary / Rule / LocalNmt，聚合 `Mixed`；
- 文档 `# hello / Good morning. / This is a complex sentence. / code block`：
  `units=3`，代码块逐字节保留；
- 质量样本 10 篇文档：document_structure **1.0**、fatal 0、数字 1.0。

## 7. P20-K：持续学习基础

### 7.1 新增 crate

`translator-learning`（API feature `learning`，默认关闭）：

| 能力 | 实现 |
|---|---|
| 隐私分级 | `PrivacyLevel::{Off,Local,AuthorizedCorpus,RemoteTransfer}` |
| 学习记录 | SQLite，按源文/语言对/原因/上下文指纹去重聚合 |
| 原因分类 | `FallbackReason`：缺词/缺短语/消歧失败/规则未覆盖/规则拒绝/复杂句/长上下文/显式模型/引擎回退 |
| 候选提取 | 单词、短语、保守句式模板（如 `Please restart the {object}.`） |
| 审核状态 | Raw → Aggregated → Corroborated → Verified/Rejected → Released |
| 发布 | staging 版本、manifest、sha256、ResourceStore 安装/激活/回滚 |
| 隐私删除 | `clear_all()`、保留期清理 |
| 统计 | `LearningStats`，与翻译 `RouteStats` 分开 |

### 7.2 默认隐私

| 级别 | 行为 |
|---|---|
| `Off`（默认） | 不创建学习线程、不写记录；聚合诊断也不落正文 |
| `Local` | 保存必要源文与局部上下文；默认不保存模型译文 |
| `AuthorizedCorpus` | 可保存候选译文，但状态仍是 Raw，不是正确标签 |
| `RemoteTransfer` | 仅授权标记；本版本无网络实现 |

敏感内容（API key/password/token/Bearer/私钥标记）命中时**跳过整条记录**，
不做“无法保证的脱敏”。这只是启发式，不是通用 DLP（见 Q-072）。

### 7.3 主链隔离

- 记录在后台线程完成；
- 主链只做一次 `try_send`；
- 队列满、数据库错误、隐私拒绝都不会让翻译失败；
- `LearningRuntimeStats` 单独统计 submitted/recorded/skipped/errors/queue_full；
- `Translator::shutdown()` 会 flush 学习队列。

### 7.4 发布与回滚

`stage_release` 产出 ResourceStore v2 清单兼容目录：

```text
knowledge.learning.en-zh/
  knowledge.json      # 候选知识 payload
  manifest.json       # payload_schema_version=knowledge.json.v1
  LICENSE.txt
```

资源类型新增 `ResourceKind::Knowledge` + `PayloadSchema::KnowledgeJsonV1`。
发布**不会自动改词典**；它只是可审核、可回滚的候选资源。
测试已验证：`install_from_dir` → 激活 v2 → `rollback` 回 v1。

### 7.5 已验证

- 默认 Off 不写记录；
- Local 只存源文；
- AuthorizedCorpus 保存候选译文但未验证；
- 敏感凭据跳过；
- 不同上下文 `bank` 不合并；
- 未验证候选不能 stage；
- 审核→发布→回滚完整闭环；
- ResourceStore 安装/激活/回滚；
- clear_all 删除记录/候选。

## 12. 结论

P17-A 完成了“真实源码核验 → 统一规划 → 共享证据 → 本地/远程兜底 → Mixed 轨迹 →
学习链基础 → 全量回归”的闭环，并保持 P16-R 的 320 句自动质量基线不变。

但这不是语言能力建设完成：

- 词典/短语/搭配没有大规模新增；
- 规则仍是 40 条完整模板，没有参数化/组合语法；
- 学习链只完成可运行基础，没有真实长期数据与人工审核；
- 远程只有接口/授权/缓存统一，没有真实服务验证；
- 人工评审仍 **PENDING_HUMAN**。

因此结论保持 **Conditional**：架构方向已落地并可复核，长期语言能力仍需
P18-L / P19-G / P20-K / P21-M 持续推进。
