# 轻量跨平台翻译 SDK — 资源候选与备选清单

> 文档版本：v1.0（候选评估 / 不等于已集成）  
> 核对日期：2026-11-05  
> 本文只列**字典/语料、规则/分析器、语言识别、翻译模型、推理运行时与授权/替换关系**。架构和公共 API 以 `01_翻译SDK完整开发设计.md` 为准。

## 1. 评估原则与术语

- **核心硬约束**：Windows、Ubuntu、macOS、Android 可运行；低内存；离线默认；资源可以单独安装/删除；不绑定唯一 runtime。
- **资源级别**：A = 首批候选；B = 备选；C = 研究或非默认；`验证中` 表示尚未在本项目完成集成。
- **三个不同大小**：源数据/模型磁盘体积、实际模型权重、**推理峰值 RAM**。不可混用。
- **许可优先级**：优先宽松许可；CC BY-SA 和 GPL 需审查再分发与衍生作品义务；CC BY-NC 不能用于普通商业分发。
- **动态变更**：模型数量、语言覆盖、文件体积、许可证可能随版本变化，发布必须固定**精确来源 revision/checksum**，不能只依赖首页信息。
- **特别更正**：旧仓库 `mozilla/firefox-translations-models` 已归档（2025-12-15）；当前以 `mozilla/translations` 和 Firefox 模型注册表为准，不应把旧仓库当成新模型唯一来源。

## 2. 词典与词条数据（可按语言包分发）

| 优先 | 资源 | 语言/内容 | 可用形式 | 典型用途 | 许可证及风险 | 替换路径 |
|---|---|---|---|---|---|---|
| A | **CC-CEDICT** | 汉字简繁、拼音、中→英释义 | 文本词条 | 中英核心词典 | CC BY-SA；确认具体发布版本 | 自建合法来源词典 / Kaikki 中文词条 |
| A | **Kaikki / Wiktionary Extracts** | 多语言词条、词性、词形、释义 | JSONL | 多语言扩展主来源 | Wiktionary 授权及各条来源/署名；需保留衍生数据义务 | FreeDict / 自建词库 |
| A | **JMdict / EDRDG** | 日语词条、假名、词性、多语释义 | XML | 日语查词 | 按 EDRDG 当前条款，必要署名 | Kaikki 日语 / 其他授权词典 |
| B | **FreeDict** | 多双语词典 | TEI XML、DICT 等 | 补充薄弱语言对 | 各词典授权不同，逐包审核 | Kaikki / 自建数据 |
| B | **自有术语库** | 编程、医学、游戏等自定义 | CSV/TSV/JSON → FST/SQLite | 提高术语稳定性 | 取决于数据来源 | 可覆盖任何公共词典 |
| C | **Apertium 双语词典** | 依语言对而异 | `.dix` 等 | 规则引擎研究 | 语言包多为 copyleft；慎用闭源分发 | 自研规则词条 |

### 2.2 字典处理建议

**编译期转换，不在用户设备上解析全量 JSON/XML**：源文件 → 按语言/词性过滤 → 编码规范化 → 词义去重 → 保存 `source_id/license` → FST（索引）+ SQLite（释义）→ Package Manifest。只读文件可 mmap；安装不同许可的数据包时保持独立文件和可追溯词条 ID。

不要把不同来源的词条重新混合后丢失许可证信息；不得因“软件能商业使用”而默认数据库内容可闭源再许可。日语/中文分词词典与普通翻译词典的许可分别核查。

## 3. 文本分析与规则候选

| 优先 | 候选 | 功能 | Rust/移动适配 | 注意及替代 |
|---|---|---|---|---|
| A | **Unicode normalization**（Rust crate） | NFC/NFKC、字符归一化 | 纯 Rust | 默认 NFC；NFKC 可能改变代码/符号语义 |
| A | **自研规则 DSL** | URL/变量保护、术语校验、精确短语、分句路由 | 可编译为紧凑二进制 | 保持简单、有测试的规则，避免设计全语法机器翻译 |
| A | **Lindera** | 日/中/韩词法分析、词性标注 | 纯 Rust，外部词典可选 | 词法词典大小和各自许可分开审核 |
| B | **Apertium 的 FST/规则理念** | 词形生成、语言对规则 | C++ 生态，参考而非直接依赖 | 大量语言资源授权需要审查；端侧整体移植成本高 |
| B | **Unicode 脚本检测 + 自定义启发式** | 辅助语言检测 | 极轻量 | 中日汉字共享，不能作为唯一语言识别依据 |
| C | **完整规则机器翻译** | 单独处理整句 | 工程范围大 | v0.1 不推荐 |

- Lindera：https://github.com/lindera/lindera ；文档：https://lindera.github.io/lindera/
- Apertium：https://github.com/apertium/apertium

**建议规则包格式**：`schema_version / id / source / target / priority / normalizers / protected_patterns / exact_phrases / glossary_constraints / tests / provenance`。规则包需可完全替换；不依赖某 NMT 后端内部 Tokenizer。

## 5. 本地神经翻译模型候选

| 优先 | 模型 | 语言覆盖 | 体积/量化 | 主要优势 | 主要风险/授权 | 推荐用途 |
|---|---|---|---|---|---|---|
| A | **Firefox Translations Marian（tiny / base-memory / base）** | 以当前官方 registry 为准 | 小、中、较大多档；逐包查文件 | 为消费端 CPU 翻译优化，已有 Bergamot 推理链 | 并非所有语言对均存在；模型文件授权及依赖需逐项确认 | 第一版主力 PoC |
| A/B | **Helsinki-NLP OPUS-MT / MarianMT** | 按语言对 | 常见模型 FP32 约数百 MB，量化需测试 | 语言对独立包，生态较成熟 | 许可证按 checkpoint 变化；ncnn 转换未保证 | Firefox 覆盖不足时替换 |
| B | **M2M100 418M** | 约 100 种语言多方向 | 418M 参数；INT8 权重理论约 418 MB | 单模型多语言，不强制经英语中转 | 真正 RAM 与推理延迟较大；需要 seq2seq 后端适配；MIT | 桌面选装多语言 |
| C | **MADLAD-400 3B MT** | 400+ 语言 | 3B 参数；INT8 权重理论约 3 GB | 语言广、较大能力 | 与低内存目标冲突，转换及速度待验证；Apache 2.0（按模型页） | 高配选装、离线对照 |
| C（非商业研究） | **NLLB-200 distilled 600M** | 约 200 种语言 | 600M 参数 | 多语言质量研究 | **CC BY-NC 4.0**；不做商业默认 | 学术对照 |

### 5.1 模型链接

- Mozilla 当前项目：https://github.com/mozilla/translations
- Firefox 当前注册表：https://mozilla.github.io/translations/firefox-models/
- 旧归档仓库（仅作历史参考）：https://github.com/mozilla/firefox-translations-models
- OPUS-MT 模型集合：https://huggingface.co/Helsinki-NLP
- OPUS-MT 英→中示例：https://huggingface.co/Helsinki-NLP/opus-mt-en-zh
- M2M100 418M：https://huggingface.co/facebook/m2m100_418M
- MADLAD 400 3B MT：https://huggingface.co/jbochi/madlad400-3b-mt
- NLLB 600M：https://huggingface.co/facebook/nllb-200-distilled-600M

### 5.2 需要特别验证的事项

1. **目标语言对**：以实际 registry/model card 核实中↔英、日↔英、日↔中；可能需要英语中转，但会降低质量并增加延迟。
2. **模型不是 Runtime**：Marian 模型必须匹配其 tokenizer/词表/架构；Bergamot 模型不等于 ncnn `.param/.bin`。
3. **量化后的准确率**：对专业术语、数字、占位符、低频词和日韩文字做回归测试；不要只看总 BLEU。
4. **实际内存**：分开测试冷启动 RSS、已加载 RSS、逐句峰值、长句峰值和卸载后的 RSS。
5. **来源固定**：模型包必须记录 revision、下载 URL、SHA-256、推理框架版本、许可证和质量报告。

## 6. 推理 Runtime 与后端候选

| 优先 | Runtime | 运行平台与重点 | Rust 集成 | 适配模型 | 风险/决策 |
|---|---|---|---|---|---|
| A | **Bergamot / Marian** | 消费端 CPU、原生与 Wasm | C++ FFI adapter | Firefox Marian 格式 | 先验证 Android native 构建、大小、许可证、模型覆盖 |
| A/B | **ncnn** | Android/桌面 CPU + Vulkan、低内存 | C API/FFI | 转换过且算子兼容的模型 | **Encoder–Decoder 生成链必须自己适配验证** |
| B | **ONNX Runtime** | Windows/Linux/macOS/Android 等 | `ort`/原生绑定 | ONNX seq2seq | ONNX 转换与解码集成、运行库占用 |
| B | **CTranslate2** | 优化 Transformer CPU/CUDA | C++ FFI / 第三方绑定 | Marian、M2M100 等 | Android 构建与库体积必须验证 |
| C | **Burn** | Rust 原生；WGPU/CPU 等 | Rust crate | 需已有/自研模型实现 | 高开发成本；适合作为长期 GPU 后端 |
| C | **Candle** | Rust 原生 CPU/CUDA/Metal | Rust crate | 已有 Marian 示例可借鉴 | GPU 跨平台覆盖不完全相同，需另行测量 |

**后端替换决策必须基于同一模型/同一设备的实测**，不以“轻量”“原生 Rust”等标签直接下结论。ncnn 的模型和推理工作区都需进行 memory profiler；Bergamot 应先作为质量/内存基线。

- Bergamot：https://github.com/browsermt/bergamot-translator
- Firefox 对 Bergamot 的技术说明：https://firefox-source-docs.mozilla.org/toolkit/components/translations/resources/03_bergamot.html
- ncnn：https://github.com/Tencent/ncnn
- ONNX Runtime：https://onnxruntime.ai/
- CTranslate2：https://github.com/OpenNMT/CTranslate2
- Burn：https://github.com/tracel-ai/burn
- Candle：https://github.com/huggingface/candle

## 7. 资源包替换矩阵（不修改公共 API）

| 能力 | 首选资源 | 触发替换的条件 | 备选资源 | 需通过的验证 |
|---|---|---|---|---|
| 中英词典 | CC-CEDICT | 许可/覆盖/质量不满足 | Kaikki + 自有术语 | 样本查词、来源追溯 |
| 日语词典 | JMdict | 许可/体积不满足 | Kaikki 日语 | 词形、读音、释义 |
| 多语言词典 | Kaikki | 包体太大/授权成本 | FreeDict 选装 | 数据格式、许可、查找速度 |
| 日语词法 | Lindera + 独立词典 | 包过大/授权问题 | 轻量规则/其他 tokenizer | 分词准确性、峰值 RAM |
| 语言识别 | fastText ftz | 授权/误判 | Unicode 启发式 + 其他小模型 | 短文本、中文/日文混淆 |
| 轻量 NMT | Firefox Marian + Bergamot | 语言缺失/Android 不达标 | OPUS-MT + ORT/CT2 | 翻译质量、峰值 RAM、时延 |
| NMT 推理 runtime | Bergamot | 无法部署目标平台 | ncnn（验证通过后）/ORT | 同模型契约测试及基准 |
| 单模型多语言 | M2M100 | 设备内存超预算 | 多个小语言对包 | 包体、切换速度、质量 |
| 远程翻译 | 任意 OpenAI 兼容接口 | 无法连接/供应商变更 | 新 Provider 插件 | 网络授权、密钥、重试 |

**插件契约应独立于资源格式**：字典包可替换而词条类型不变；模型包可替换而 `Translator::translate()` 不变；推理 Runtime 可替换而 `EngineDescriptor/LoadedModel` 接口不变。

## 8. 推荐分发组合

### 8.1 最小 SDK（默认安装）

- Rust core + registry + resource manager + FST/SQLite dictionary adapter。
- 少量词条及基础规则（或完全空资源启动）。
- GPU/外部 LLM/大型语言识别模型不作为必需组件。
- 目标：无模型空闲时额外 RAM 尽量 < 10–20 MB；**待实测**。

### 8.2 常用中英包

- CC-CEDICT + 精确短语包 + 轻量分词/语言检测。
- 英↔中各自一个经过验证的 Marian/Firefox/OPUS-MT 方向模型（如果确实存在且授权符合目标发行方式）。
- 模型按需加载；一时刻只保留一个热模型；空闲 TTL 卸载。

### 8.3 日语扩展包

- JMdict + Lindera 形态词典 + 日英或日中可用模型（逐方向核实）。
- 如果需中转英语，UI/SDK 返回明确警告和更高延迟预期。

### 8.4 高级多语言可选包

- M2M100 418M 及其专用 runtime；不应暗中安装到 Android 低内存设备。
- 高配桌面可安装更大模型，但默认仍使用低内存策略。

## 9. 采购/引用/发布审核表（必须填写）

每个资源包发行前在 `provenance.json` 中补全：

```json
{
  "resource_id": "model.example.en-zh",
  "source_url": "https://example.invalid/model",
  "source_revision": "REQUIRED",
  "download_sha256": "REQUIRED",
  "license_spdx": "REQUIRED_OR_LICENSE_REF",
  "license_text_path": "LICENSE.txt",
  "notice_text_path": "NOTICE.txt",
  "redistribution_review": "pending",
  "commercial_use_review": "pending",
  "derived_from": [],
  "build_tool_versions": {},
  "benchmarks": {
    "device": null,
    "cold_load_ms": null,
    "peak_rss_mb": null,
    "latency_p95_ms": null
  }

```

**示例中的 `.invalid` 地址和 `REQUIRED` 必须由发布流水线替换，未完成审核不得发布。** 审核检查代码库许可证、模型权重许可证、训练数据或词典内容的来源义务、商标和署名要求；必要时寻求专业法律意见。

## 10. PoC 测试矩阵与筛选门槛

| 编号 | 样本/设备 | 必须测量 | 判定 |
|---|---|---|---|
| D-01 | 中英 1 万词条索引 | 查询 p50/p95、索引内存 | 字典替换接口不变 |
| D-02 | 10 万词条/不同来源 | 包体、mmap RSS、许可证溯源 | 词条无来源丢失 |
| R-01 | 规则处理短句/代码 | 占位符完整性、误替换 | 关键标记零丢失 |
| L-01 | 中英日混合短文本 | LID 误判率和置信度 | 不确定时返回多个候选 |
| N-01 | 20/100/500 字文本 | 质量、p50/p95、峰值 RSS | 低于设备预算或明确降级 |
| N-02 | Android ARM64 物理机 | CPU/GPU、温度、5–10 分钟稳定性 | 不崩溃、不持续泄漏 |
| N-03 | Bergamot vs ncnn/ORT | **同模型**同参数测试 | 记录差异，按数据决策 |
| N-04 | 多语言中转 | 质量下降、两次推理时延 | 标记 pivot route |
| P-01 | 卸载/热更新/损坏资源 | 生命周期与回滚 | 无使用中销毁、旧包可恢复 |

初始建议 Android Lite 模型相关推理峰值预算 **200–250 MB**，不是任何候选模型的实测保证；若达不到，优先缩小模型、改用更少语言对、更低并发或调整产品目标。

## 11. 需要优先做出的资源决策

1. **先锁定中↔英两个方向的真实轻量模型**：从 Firefox 当前 registry 寻找；缺失则查 OPUS-MT；记录各自质量与授权。
2. **先完成字典包规范**：CC-CEDICT 与 Kaikki 的一小部分数据，保留 provenance，测量 FST/SQLite 实际 RAM。
3. **跑 Bergamot 基线**：用同一组文本确认 NMT 的准确率、加载时间和峰值内存。
4. **再评估 ncnn**：仅在发现可完整支持的 seq2seq 模型/算子后投入优化；不要以转换成功作为可用标准。
5. **最后扩充语言**：日语与更多语言按资源包独立增加，避免最小发行物膨胀。

---

**结论**：默认资源采用“**最小词典/规则 + 独立语言包 + 轻量 Marian 翻译包**”；Bergamot 用作首期可行性与质量基线，ncnn 是值得投入的低内存候选，但其具体 Encoder–Decoder 模型适配须经过完整验证。词库、规则、模型和 runtime 均可单独替换，不应影响主 SDK 的稳定公共接口。
