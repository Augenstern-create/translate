## 1. LID 注入

### 1.1 实现

- `CoordinatorConfig.language_identifier: Option<Arc<dyn LanguageIdentifier>>`；
- `TranslatorBuilder::language_identifier(identifier)`；
- 默认 `None` → 原有 Unicode 启发式，P94-01 行为保持不变；
- 注入时：
  - `Translator::detect_language` 使用注入实现；
  - 未显式给 `source` 的翻译也使用注入实现选首个候选；
  - 两个 Translator 各持自己的 `Arc`，互不串（P94-03）。
- `LanguageIdentifier`/`MorphologyAnalyzer` 从 `translator-core` 重新导出，宿主不需要第二套接口。

### 1.2 测试

| ID | 结果 | 证据 |
|---|---|---|
| P94-01 默认构建不启用 fastText | **PASS** | `p94_01_默认detect行为保持启发式` |
| P94-02 注入 fastText（用固定测试识别器验证注入路径） | **PASS** | `p94_02_p94_03_注入的lid生效且实例隔离` |
| P94-03 两个 Translator 不同 LID | **PASS** | 同上：en / ja 各自返回 |
| P94-04 fastText 模型未安装 | **PASS** | `p94_04_模型缺失返回明确错误`（可选 feature） |

> P94-02 的“fastText 注入”由固定测试识别器覆盖注入路径；真实 `FastTextIdentifier` 已在 P9.2 做同集对照。JNI 侧暂无 LID 配置项，见偏差 P9.4-D01。

## 2. lemma 辅助查词

### 2.1 实现

- `TranslatorBuilder::lemmatizer(Arc<dyn MorphologyAnalyzer>)`；
- `Coordinator::lookup`：
  1. 原词精确查询（所有 provider）；
  2. 仅在**原词结果为空**时，调用 lemmatizer 取最多 3 个候选；
  3. 每个候选查词，按 `(headword, source_id)` 去重后追加；
  4. 原词命中时**不**运行 lemma，不覆盖用户输入。
- 返回条目保留原词/lemma 的 `headword`、`source_id`、`source_license`；不修改 `TranslateRequest` 或受保护跨度。

### 2.2 测试

| ID | 结果 | 证据 |
|---|---|---|
| P94-05 `children` 未命中后 `child` 命中 | **PASS** | `p94_05_p94_06_lemma只在原词未命中时兜底` |
| P94-06 原词已命中不被覆盖 | **PASS** | 同上 |
| P94-07 URL/占位符不被改写 | **PASS** | `p94_07_保护文本不被lemma修改`（lookup 原样输入，返回空） |

边界：目前只注册英语规则 lemmatizer；其他语言需宿主注入自己的 `MorphologyAnalyzer`。

## 3. 同音词（P94-08）

- JNI/Translator `lookup` 通过 `DictionaryProvider` 返回 v3 `postings` 的全部条目；`はし` 在 Android 上返回橋/箸/端等 6 条。
- `DictionaryEngine::translate` 仍只返回首条（legacy API）；测试明确记录，不把“bridge”宣称为唯一正确翻译。
- 要获得多义，调用 `lookup`；P9.4 未改 `TranslationResult` 结构，避免破坏旧宿主。

## 5. EP-02 规则/术语内容摘要
