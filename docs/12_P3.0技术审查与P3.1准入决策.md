### 2.1 P0：worker **必须是进程而不是线程**

P3.0 直接证明 Marian/Bergamot 参考 CLI 在异常输入资源下可能结束整个进程。`std::panic::catch_unwind` 无法拦截 SIGSEGV/`abort()`；worker 线程也无法给主进程提供内存访问错误隔离。

**P3.1 的推荐执行模型：**

```text
translator-api
    ↓
Translation Coordinator / LocalNmtEngine (纯 Rust 逻辑)
    ↓
RuntimeTransport（trait：可替换）
    ↓
Linux 子进程 IPC：framed request/response + request_id + timeout
    ↓
bergamot-worker（进程独占 native model / 1 推理执行）
    ↓
Bergamot / Marian C++
```

- 在 P3.1-A 先实现 Mock worker 和协议测试；再将真实原生 Bergamot 放进 worker。
- 推荐用长度前缀帧承载有限大小的二进制/JSON 消息；不要把业务数据与 native stdout 日志混用，stderr 作为诊断通道。强制消息大小上限、超时和格式校验。
- 明确 `LoadModel` / `Translate` / `UnloadModel` / `Health` / `Shutdown` 消息；response 至少关联 `request_id`、状态码、耗时、worker epoch、model revision。
- worker 意外结束时，当前请求返回 `BackendFailed` / `RuntimeInitFailed`，**不应将运行中请求未经用户许可悄悄发送到 Remote LLM**。
- worker 可按受控策略重启；在未实现幂等性/副作用策略前，不自动无限重试。
- 在 Linux 子进程管理中定义 TERM→等待→KILL 的升级终止策略，并避免僵尸进程；`shutdown()` 不应永久卡住。
- `RuntimeTransport` 层不要公开 Bergamot C++ 对象；后续替换 ncnn/ORT 不需要改变 `translator-api`。

**边界说明**：进程隔离能降低原生崩溃影响宿主的风险，但不是恶意模型的安全沙箱；如需加载不可信二进制插件，应另做文件系统、权限、seccomp 等隔离评估。

### 2.2 P0：模型校验与版本快照

将四个已锁定文件视为一个**不可分割的模型资源集合**，校验至少包括：

1. 资源 Manifest 与 `models.lock.json` 的模型方向、权重格式、Tokenizer、shortlist 和 runtime 版本兼容关系。
2. 每个必需文件存在、大小正确、SHA-256 匹配；禁止路径穿越、符号链接逃逸和可变目录上的不受控替换。
3. 在 `ResourceLease` 有效期间，禁止删除该模型 revision；加载时使用已经通过校验的只读 snapshot，而不是重新解析任意用户提供路径。
4. `ResolvedExecutionPlan` 明确记录 **engine id、runtime build、model 内容摘要、Tokenizer/短名单摘要、生成参数、术语/规则版本、隐私域**，进入缓存键；不能仅使用 `model_id@version` 字符串。
5. 如引入内容校验缓存，须与不可变内容标识/可信文件句柄绑定；**仅依赖 mtime、size 或文件名不能证明安全性**。

在进程模型下仍可能存在校验之后文件被修改的 TOCTOU 问题；P3.1 的基本版本可通过受控不可变版本目录、文件权限、租约和只读快照缓解。若运行场景包含不可信本机写入者，需进一步使用打开的文件句柄或安全复制到隔离工作目录，不能把普通目录名视作加密信任边界。

### 2.3 P0：占位符保护必须经过**真实 NMT**

不要假设把 `{name}` 替换成 `__PLACEHOLDER_1__` 后模型一定会照抄。需要测试多个格式候选，包括标记被改变、重复、重排、丢失以及模型插入额外标记时的恢复能力。对结构性文本，保留原貌应优先于"看起来流畅"的译文。

建议最小测试集：

| 编号 | 输入重点 | 必须成立的性质 |
|---|---|---|
| SP-01 | `{name}` 与 `{order_id}` | 数量、内容与身份完整；任何缺失显式失败 |
| SP-02 | URL + 邮箱 + 中文句号 | URL/邮箱字节保持原样 |
| SP-03 | 反引号包围命令 | 代码与反引号结构必须保持 |
| SP-04 | 相邻、重复、嵌套样式标记 | 区分相同字面量与不同标记实例 |
| SP-05 | 标记出现在句首/句末、空文本 | 不编造、不吞并 |
| SP-06 | 多句跨分段标记 | 不跨请求误还原 |
| SP-07 | 标记被删除/复制/篡改 | `IntegrityFailure`，不返回伪正常译文 |
| SP-08 | 译文语序改变 | 可允许标记位置调整，但一一对应必须成立 |

P3.1 可以保留内部文本标记机制，**不需要先向 `InferenceBackend` 暴露 `ProtectedSpan`**。如果真实模型仍不能可靠保留标记，应将"分段/受保护跨度之外翻译"作为对照实现，而不是无限试探提示词或无条件使用正则替换。

现有 `strict_placeholder_restore` 必须用于 SDK 的真实 NMT 默认安全策略；若为了向后兼容保留宽松模式，输出必须标出失败、不能静默成功。

### 2.4 P1：内存与性能测量改进

P3.1 至少分开采集：

- `host_rss`、`worker_rss`、`combined_rss`（内存预算不能只计宿主）。

## 3. P3.1 实施顺序与每步验收

| 顺序 | 子阶段 | 交付物 | 必须通过的验收 |
|---|---|---|---|

| B | 模型包安全加载 + Bergamot worker | model manifest 兼容性、四文件校验、native 适配 | 真模型译 `Hello world!`；文件缺失/截断不得杀死宿主 |
| C | 真实占位符保护 | 保护扫描、token 映射、还原、严格失败 | SP-01～08，尤其 `{name}` 不丢、反引号不改 |

### 3.1 对公共 API 的明确限制

- `translator-api` 保持 UI 无关，不引入 Bergamot 的 C++ 类型、Linux pid 或 socket 句柄。
- 编译默认 feature 仍可不带 native runtime 构建；Bergamot 实现必须是可选插件。
- 进程 transport 可以只在 Linux 实现，但其 trait 应可替换；非 Linux 返回明确的 `CapabilityUnavailable`，不放空实现。
- 不把 worker 的原始 stdout/stderr 或原文直接写入集中日志；诊断仅记录请求 ID、模型 revision、耗时、匿名错误码（明文文本须经宿主显式授权）。
- `translate()` 和 `translate_with_diagnostics()` 继续共用同一条执行路径，不能产生两种译文。
- `LocalOnly` / `AutoLocalFirst` 始终不自动发送网络请求；worker 失败只是本地故障，不是云端授权。

### 3.2 失败路径及建议错误映射

| 情形 | 对外错误类别 | 是否允许安全重试 |
|---|---|---|
| 模型文件缺失 | `ResourceNotInstalled` | 安装后手动重试 |
| SHA/大小不符 | `IntegrityFailure` | 重新下载/重装，不能原地忽略 |
| runtime/模型格式不兼容 | `CapabilityUnavailable` 或 `RuntimeInitFailed` | 更换兼容组件后重试 |
| worker 启动失败 | `RuntimeInitFailed` | 有限重启，报告原因 |
| worker 异常退出（SIGSEGV/abort） | `BackendFailed` | 当前请求失败；按策略有限恢复 |
| 请求排队超时 | `Timeout` | 可由宿主决定重试 |
| 推理超时且 native 不可中断 | `Timeout` | 需终止独占 worker，确认清理后恢复 |
| 取消等待 | `Cancelled` | 不代表原生请求已停止；必须明确状态 |
| 占位符恢复缺失/重复 | `IntegrityFailure` | 可使用分段策略再次尝试；不得静默输出 |
| 超过资源预算 | `OutOfBudget` | 降低并发/更换小模型后重试 |

## 6. 最终决策与阶段边界

1. **P3.0：有条件 PASS。** 本阶段目标为原生真实模型可行性验证，核心目标已达到；未完成项如实列 pending，不要求重做。
2. **批准进入 P3.1-A。** 首先是 worker 进程协议和 Mock 异常隔离，不是直接把 C++ 模型句柄绑定进宿主进程。
3. **默认单 worker/单请求。** 413.8 MiB 为 P3.0 原生单线程峰值参考，不可宣称是 Rust SDK 的总内存指标。
4. **真实模型占位符保护是硬门槛。** 模型吞 `{name}` 已有报告证据；P3.1 不能仅凭 Mock 通过宣布完成。
5. **模型权重暂不随包分发。** 许可证未确认前仅研究/本地测试，发行前单独审核。
6. **跨平台仍然是设计目标，不是当前验收范围。** Ubuntu/Linux 先交付；其它系统仅保留接口和可替换实现位置。
7. **原有 P0–P2-S 功能不能回退。** 真实 NMT 插件必须由可选 feature 装配；空资源/Mock 构建继续通过。

### 建议并入 `docs/01` 的决策（避免覆盖现有 ADR）

`docs/11` 已说明 ADR-024～028 已用于 Linux-first、参考运行时、模型内容身份、worker 所有权和权重不入库。**本审查不再重新占用这些编号**。可在既有 ADR 下补充：

- "Native Runtime Worker Ownership"明确为**进程级故障隔离**，不能把线程独占误称为宿主崩溃隔离。
- "Model Revision Is Content Identity"明确包含权重、Tokenizer、shortlist、生成参数和 runtime build。
- "Model Weights Not Vendored"继续保持发行阻断，直到权重授权核实。
- 可另新增 ADR（编号从当前最新基线顺延）记录"真实 NMT 的严格占位符完整性策略"，前提是核对 `docs/01` 实际占用编号。

## 7. 可复现性核对与后续审查输入

审查 P3.1 时应要求提交：

- Rust 源码与 `Cargo.lock`、native worker 薄 ABI 实现、可重现构建脚本和 CI 日志。
- 实际使用的模型包 Manifest、已校验四文件摘要、构建/模型锁版本。
- `translator-cli` 通过公共 API 真实翻译的完整命令与输出。
- 故障注入原始日志：模型损坏、worker SIGSEGV/abort、超时/取消、重复请求与安全退出。
- 单 worker host/worker RSS/PSS、100～1000 次热请求、卸载后的内存趋势。
- 保护跨度金样本与逐条结果、特别是 `{name}`/`{order_id}`、反引号代码、URL/邮箱。
- 与 P3.0 原生基线的同设备/同配置对照，若差异明显说明来自 IPC、Tokenizer、worker 启动还是执行配置。

**审核人结论**：P3.0 的价值在于已经锁定并证明真实翻译链路可用。P3.1 要解决的不是"能不能翻"，而是"在不拖垮宿主、不破坏文本、不错误复用模型/缓存的前提下，稳定地翻"。
